# QuestRules — точка входа для ИИ-агента

> **Если ты ИИ-агент — читай этот файл первым.** Он объясняет, зачем нужен набор
> инструкций, как устроен весь процесс, и отправляет к нужному файлу за деталями.
> Версия набора: **0.61**. Раньше это был один файл `QuestRules.md`; теперь он
> разбит на целевые инструкции в `docs/`.
>
> Набор — про разбор книги: вход (текст), выход (пакет файлов) и формат этого пакета.
> Проигрывание пакетов живёт в отдельном проекте интерфейса со своей версией.

## 0. О документе и наборе инструкций

### 0.1. Назначение

Набор отвечает на два вопроса:

1. **Что делать с входным текстом книги** — [docs/conversion.md](docs/conversion.md).
2. **Каким должен получиться выход**: из чего состоит пакет и как описываются сцены,
   переходы, манифест, предметы, статусы, иллюстрации, музыка.

Роль набора — **исполняемая инструкция для ИИ-агента**. По нему ИИ-конвертер разбирает
произвольную книгу-игру (или пишет новую) и выдаёт пакет, который движок читает и
проверяет. Для человека это те же документы: они описывают формат и объясняют, почему
правила именно такие.

**Главный артефакт проекта — этот набор инструкций, а не конвертеры.** Любой
скрипт-конвертер под конкретную книгу — одноразовый побочный продукт: он ускоряет
разбор, но ничего не говорит о формате. Формат живёт здесь.

### 0.4. Режим ИИ-конвертации

> **ВАЖНО. Результат конвертации остаётся в каталоге книги.** Все созданные файлы —
> `story.md`, `game.yaml`, `items.yaml`, `stats.yaml`, `flags.yaml`,
> `mechanics.yaml`, `review.md`, `storyGraph.md`, `soundtrack.md`,
> `illustrations.md`, `assets/` — складываются рядом с исходным текстом книги.
> Пакет не пишется в чужие каталоги: сначала его проверяет человек (шаг 12 в
> [docs/conversion.md](docs/conversion.md)), и только после этого он передаётся дальше.

Пакет может лежать отдельной папкой внутри каталога книги (например,
`kupalo-night/` рядом с PDF): имя папки должно совпадать с `id` — иначе плеер и
сейвы расходятся (`W_PKG_ID_FOLDER_MISMATCH`).

Вход: произвольный текст книги-игры — txt, md, выгрузка из PDF, HTML, текст с
номерами секций или без, с отсылками `[12]`, `(12)`, «на 12», «стр. 12», «→ 12»
или вообще без нумерации.

Выход — пакет, который **проходит валидатор без ошибок**:

```text
game.yaml      манифест: формат, id, название, стартовая сцена, метаданные сцен
story.md       все сцены: ## <ключ>, повествование, выборы
items.yaml     только если в книге есть предметы (TBD 6)
stats.yaml     только если в книге считаются характеристики (TBD 7)
flags.yaml     только если в книге есть события (TBD 7)
mechanics.yaml только если есть проверки или бои (типы fighting-fantasy/rpg)
review.md      сомнительные случаи для человека + аудит предметов и денег (§0.5, [review.md](docs/review.md))
storyGraph.md  карта ветвлений: выходы сцен, концовки, хабы, Mermaid-граф (§2.3, [story-graph.md](docs/story-graph.md))
soundtrack.md  бриф композитору: настроение каждой сцены и главы по настроению (§2, [manifest.md](docs/manifest.md))
illustrations.md  бриф художнику: что нарисовать и к каким сценам (§2, [manifest.md](docs/manifest.md))
assets/        изображения и звук, включая обложку (cover) и кадры из книги
```

Ключевые ограничения режима:

- **текст не редактируется**: ни вычитки, ни переписывания, ни «улучшения» стиля.
  Разрешены только разметка по шагу 3 в [docs/conversion.md](docs/conversion.md)
  (номер заменяется на `[А]` или удаляется, чисто адресные формулы удаляются), теги
  вариантов и слияние частичных дублей — как исключение, с `C_TEXT_DUPLICATE` и
  подтверждением человека;
- **не добавляются сцены и ветки, которых нет в книге**, и не удаляются существующие;
  исключение — страховочный вариант и концовка при тупике: `C_CONTENT_ADDED` и
  подтверждение человека;
- **линейный переход не превращается в выбор**, а авторская случайность — в выбор
  игрока;
- **не выдумывается механика**: очки, которые в книге считаются «в уме», не
  становятся статусом; предмет, упомянутый в прозе, не появляется в инвентаре без
  явного указания книги;
- решения, в которых не уверен, помечаются в отчёте, а не замалчиваются;
- **все файлы пишутся в каталог книги**: пакет должен быть проверен человеком до
  передачи в движок;
- после сборки ИИ сам разбирает отчёт с человеком (шаг 12 в [docs/conversion.md](docs/conversion.md)) — отчёт не оставляется
  человеку «на потом»; затем проходит preflight в целевом плеере (шаг 13,
  [docs/handoff.md](docs/handoff.md)).

Пошаговый алгоритм для ИИ — [docs/conversion.md](docs/conversion.md).

## 1. Принятые принципы формата

### 1.1. Основа формата: Markdown + YAML (зафиксировано, 0.4)

Разрабатывается **собственный упрощённый формат на базе Markdown + YAML**.

Почему так:

- Markdown — привычный автору текст: прозу сцены не нужно экранировать;
- YAML — структурированные поля (условия, эффекты, ассеты) без изобретения своего языка;
- формат остаётся читаемым в любом редакторе и диффабельным в системе контроля версий.

### 1.2. Игра — это данные, а не код (зафиксировано)

- произвольный пользовательский JavaScript в пакете **не поддерживается**;
- произвольный CSS **не поддерживается**: тема — только контролируемый набор токенов;
- всё поведение игры выражается декларативно: сцены, условия, эффекты, переходы.

Следствие для формата: любая конструкция должна быть проверяема статически, без
исполнения авторского кода.

### 1.3. Ориентиры (зафиксировано, 0.4)

Источники вдохновения:

- Ink;
- ChoiceScript;
- Twine;
- TinyQBN;
- INSTEAD.

Что именно заимствуется у каждого — не зафиксировано, см. TBD 2–5.
**[предложение]** зафиксировать явно: у Ink — идея компактного текстового скрипта и
переиспользуемых фрагментов, у Twine — граф сцен и темы, у ChoiceScript — проверки
характеристик и модель выборов, у TinyQBN — карточки условий, у INSTEAD — привычная
русскоязычному автору модель «объект-действие».

### 1.4. Простота важнее выразительности (зафиксировано, риск 7.2)

Правила, которые формат обязан соблюдать:

- профиль формата остаётся простым;
- имена полей — понятные, без сокращений и внутреннего жаргона;
- формат документируется, к нему даются шаблоны;
- валидатор говорит человеческими сообщениями, а не кодами ошибок.

Если конструкция делает формат мощнее, но требует объяснения на полстраницы — она
не входит в профиль формата.

### 1.5. Валидатор — часть формата (зафиксировано, 0.2)

Формат считается описанным только вместе со списком ошибок и предупреждений.
Спецификация без валидатора порождает «формат, который вроде работает, но непонятно
почему не запускается».

### 1.6. Обязательный минимум формата (зафиксировано, 0.5)

Формат обязан поддерживать механики, без которых книгу-игру нельзя разобрать:

| Возможность | Где описана |
|---|---|
| сцены, выборы, переходы | [story.md](docs/story.md) |
| условия по предметам, флагам, статусам | [manifest.md](docs/manifest.md) |
| эффекты: добавить/убрать предмет, изменить статус, установить флаг | [manifest.md](docs/manifest.md) |
| изображения сцен, саундтрек и звуки | [illustrations.md](docs/illustrations.md), [soundtrack.md](docs/soundtrack.md) |
| концовки | [story.md](docs/story.md) |
| сериализуемое состояние для сохранения | [manifest.md](docs/manifest.md) |
| статическая проверка проходимости | [manifest.md](docs/manifest.md) |

Всё, что выходит за эту таблицу (карты, таймеры, квесты), в профиль формата не
входит. Проверки и бои описаны как расширение: `mechanics.yaml`, документы типов книг
([book-types](docs/book-types/index.md)). Тема оформления — отдельное отложенное
решение (TBD 9).

## 12. Правила оформления контента

**Статус:** черновик, [предложение]. Ниже — рабочие правила, которые можно применять
уже сейчас, не дожидаясь синтаксиса.

1. Один пакет — одна игра. Название игры задаётся в манифесте, а не в именах файлов.
2. Тексты пишутся на одном языке в пределах пакета; смешение языков — предупреждение
   валидатора.
3. Ссылки только внутри пакета: переходы на сцены по идентификатору, ассеты — по
   относительному пути.
4. Идентификаторы сцен и предметов — короткие, стабильные, латиницей; переименование
   идентификатора ломает ссылки из других сцен.
5. Одна сцена — один смысловой шаг истории; длинные простыни текста разбиваются.
6. Все ассеты лежат в пакете. Внешние ссылки на картинки и звук запрещены.
7. Каждый эффект должен быть объясним одной строкой: «добавить меч в инвентарь».
   Если для объяснения нужен абзац — механика слишком сложна для формата.
8. Пакет версионируется: изменение существующих сцен, ломающее сохранения, требует
   повышения версии формата или версии игры.
9. Перед публикацией пакет проходит валидатор без ошибок; предупреждения осознанно
   приняты автором.
10. Шаблон пакета обязателен: пустая заготовка с манифестом, одной сценой и одной
    концовкой.
11. При конвертации готового текста типографика нормализуется: неразрывные пробелы
    (U+00A0) заменяются обычными, двойные пробелы схлопываются. Буква «ё» остаётся
    так, как в источнике, — это не ошибка и не правится.

  отсылок берутся из аннотаций PDF (`pdftohtml -xml` → `href="#N"`), а не
  угадываются по тексту; `pdftotext` теряет дефисы и тире на границах строк —
  текст для сверки собирается из XML, дефис склеивается только без пробела перед
  ним; «<…>» — подпись «промолчать»: в линейной сцене удаляется как навигационная
  строка, в выборе остаётся вариантом; буллет без адреса — `C_REF_UNRESOLVED`,
  фраза остаётся текстом, цель не выдумывается; числа в подписях («10 лет») — не
  отсылки; общий кадр на 8 сценах одного действия — не украшение
  (`C_IMAGE_REUSED`), порог «≥ 5 страниц» — сигнал, а не приговор; ориентир
  масштаба — один кадр на 2–3 сцены; настроения на 228 сцен ставятся чтением по
  частям, а не лексиконом (0 слабых цитат); полные дубли и варианты в одну цель
  сохраняются; пакет может быть подпапкой каталога книги, если `id` совпадает с
  её именем.
- **0.59** — опыт книги на достижениях-флагах («Летние каникулы», quest-book.ru): новый
