# Передача пакета в плеер

> Приложение к QuestRules, не часть формата. Точка входа — [AGENTS.md](../AGENTS.md).
>
> Набор описывает пакет; конкретный плеер решает, что из него показать. Этот файл
> фиксирует фактическую совместимость с MVP QUEST-166 и обязательный preflight перед
> передачей книги в каталог готовых игр.

## 1. Зачем это нужно

Пакет может быть валиден по формату и при этом выглядеть в плеере не так, как ожидал
конвертер:

- книга без предметов получает кнопку инвентаря, потому что плеер запросил
  несуществующий `items.yaml`;
- пример из документации `use: [medkit]` превращается в id `[medkit]` и падает;
- проза с `###` отображается с решётками;
- `cover` и `translator` заполнены, а библиотека их не показывает;
- сейв после правки `story.md` внезапно начинается заново.

Это не ошибки формата и не повод упрощать пакет. Это граница «парсер → плеер»,
которую нужно проверять отдельно.

## 2. Матрица поддержки MVP

### 2.1. Манифест

| Поле / возможность | MVP |
|---|---|
| `format`, `id`, `title`, `start`, `story` | читает |
| `author`, `genre`, `type`, `annotation` | показывает в библиотеке |
| `language`, `edition`, `year`, `source` | служебные, в UI не выводятся |
| `status` | в библиотеке не выводится |
| `cover`, `illustrator`, `translator` | в библиотеке не выводятся |
| `items` | читает только если ключ объявлен и файл существует |
| `stats` | читает только если ключ объявлен и файл существует |
| `start_items` | поддерживает **карту** `id: количество`; список — нет |
| `flags` | читает `flags.yaml`; условия `if: flag` работают |
| `mechanics` | читает `combat`: `count`, `attack`, `health`, `weapon`, `win`, `lose`, `preDamage`, `preDamageFrom`, `preStamina`, `threshold`, `bonusDamage` |
| `theme` | не загружает |
| `moods` | читает |
| `scenes.*` (title, image, mood, music, next, variants, ending, on_enter, shop) | читает в поддерживаемом подмножестве |

### 2.2. Эффекты и условия

| Конструкция | MVP |
|---|---|
| `if: has_item …`, `stat …`, `and/or/not` | применяет |
| `if: flag …` | применяет к флагам из `flags.yaml` и установленным `set` |
| `take`, `drop`, `set`, `stat` в `on_enter` | применяет |
| `use` в `on_enter` | не применяет |
| `set` (флаги) | применяет |
| `take`, `use`, `drop`, `set`, `stat` на выборе | применяет |
| `set` на выборе | применяет |
| список в `use` | не поддерживает: `use` — один bare id |
| список в `drop` на выборе | не поддерживает; на `on_enter` список работает |
| `drop` списком в `on_enter` | применяет |
| `stat: {money: -200}` | применяет; вложенные скобки должны разбираться целиком |
| `stats.show: false` | игнорирует |
| `images: []` у сцены | игнорирует; используется только `image` |
| `mechanics.yaml` (бои) | ведёт полный бой; `preDamage`/`preStamina` — до раунда, `threshold` — особый порог; все 39 боёв ZombieBlood заполнены |
| `scenes.*.shop` | покупки: списывает `money`, выдаёт предмет, сохраняет сейв |

### 2.3. Отображение

- Библиотека: `title`, `author`, `genre`, `type`, `annotation`, прогресс.
- `genre` очищается от суффикса «книга-игра»; лучше не писать его в `genre` вовсе.
- Отсутствующие `author`/`genre`/`annotation` показываются как `—`.
- Типы: `storybook` → «стори-бук», `fighting-fantasy` → «фентези-батл»,
  `hybrid` → «гибрид», `rpg` → «рпг».
- Кнопка характеристик есть только при `stats.yaml`; кнопка инвентаря — только если
  есть предметы. На десктопе и мобильном это иконки 30×30 с `aria-label` и `title`;
  сводки открываются в панелях.
- `cover` в библиотеке не показывается; не считай это дефектом пакета.
- `status: fragment` не выводится в карточке; факт фрагмента фиксируется в `review.md`.

## 3. Обязательный preflight

### 3.1. Пакет и парсер

- [ ] `game.yaml` и `story.md` на месте; `format: quest/1`.
- [ ] Парсер целевого плеера даёт **0 ошибок**; предупреждения прочитаны.
- [ ] Нет `.parse-report`/E_*-ошибок при открытии книги.
- [ ] Достижимость проверена; недостижимые сцены/концовки подтверждены в `review.md`;
      листовые сцены помечены `ending: true`.
- [ ] Нет тупиков, кроме подтверждённых в `review.md`.
- [ ] Числовые ключи в YAML в кавычках.
- [ ] `id` совпадает с именем папки пакета (иначе библиотека и сейвы могут
      разойтись); валидатор — `W_PKG_ID_FOLDER_MISMATCH`.

### 3.2. Файлы и ассеты

- [ ] `items.yaml`/`stats.yaml`/`flags.yaml` существуют только если нужны; ключ в
      манифесте есть только при наличии файла.
- [ ] Нет пустых `items.yaml`/`stats.yaml` «на всякий случай».
- [ ] Все `image`, `music`, `cover` существуют, пути относительные, регистр совпадает.
- [ ] Нет ссылок `..`, абсолютных путей и внешних URL.
- [ ] Имена файлов ASCII, без пробелов.

### 3.3. Смысловые проверки

- [ ] У каждого проверяемого предмета есть источник; аудит предметов заполнен.
- [ ] Деньги/статы: стартовое значение названо, траты не уходят ниже `min`.
- [ ] `on_enter` не стоит в цикле, если эффект не должен повторяться.
- [ ] В прозе не осталось `{stat: …}`, `{if: …}` и прочих маркеров.
- [ ] Нет Markdown-артефактов (`###`, `**`), если плеер их не рендерит.
- [ ] `type` и `status` подтверждены человеком.

### 3.4. UI smoke в MVP

- [ ] библиотека открывается, книга в списке, жанр/тип читаемы;
- [ ] карточка раскрывается, автор/аннотация/прогресс на месте;
- [ ] «СТАРТ» ведёт на BOOK LOADER, затем на первую сцену;
- [ ] нет `.parse-report`;
- [ ] меню статов/инвентаря соответствуют данным книги (лишних нет);
- [ ] первая иллюстрация открывается и закрывается;
- [ ] сцена проходится выбором и клавиатурой;
- [ ] боевая сцена открывает терминал, а не обычную кнопку «ДАЛЕЕ»;
- [ ] сохранение продолжает с той же сцены;
- [ ] POWER-перезапуск сбрасывает прогресс и показывает BOOK LOADER;
- [ ] мобильный портрет: иконки, скрытые подписи, нет горизонтального скролла.

### 3.5. Книга, у которой сюжет держится на флагах

Если развилки — «Если отмечено «…»» (достижения, коды, события), по формату это
`flags.yaml` + `if: flag`. MVP читает `flags.yaml`, применяет `set` в `on_enter` и на
выборе и проверяет `if: flag`; установленные флаги лежат в сейве.

Проверяй на «Летних каникулах» (57 сцен, 13 условных вариантов, 9 флагов):

- [ ] все `set`-идентификаторы объявлены в `flags.yaml`;
- [ ] `set` срабатывает при входе, в том числе в стартовой сцене;
- [ ] условный вариант появляется после установки флага и исчезает без него;
- [ ] после перезагрузки сейв сохраняет флаги;
- [ ] загрузка сейва сразу в сцену не применяет её `on_enter` — для проверки ставь
      сейв на сцену-предшественник.

Если целевой плеер **не** поддерживает флаги, не «разблокируй» условные варианты
молча: либо булевы статусы 0/1 (это обход, `C_MECHANICS_ADDED`), либо блокер
`C_FLAG_ENGINE_UNSUPPORTED` в `review.md`. Это меняет сюжет книги, а не только UI.

**Проверено в MVP:** путь `1 → 5 → 25 → 26 → 2` устанавливает `kirill_question`;
в §12 без флага доступен только «ВАРИАНТ Б», с флагом — «ВАРИАНТ А» и «ВАРИАНТ Б»;
флаги сохраняются в сейве. Книга проходит целиком, расчёт «39 / 1» относится к
плееру без поддержки флагов.

### 3.6. Бой

MVP ведёт бой как продолжение текста главы: строки `РАУНД`, `Противник`, `Персонаж`
и журнал боя дописываются абзацами в той же прокручиваемой области, что и сцена.
Действия оформлены вариантами перехода; бросок кубика показывается явно и анимированно.
После победы бой переходит в `win`, после смерти показывает «ВЫ ПОГИБЛИ»,
«Выносливость 0 — приключение окончено», повтор из состояния перед входом в сцену
или выход в библиотеку. Управление: стрелки — выбор, Enter/Space — активация,
цифры — выбор по номеру.

Что уже работает:

- оружие из `items.yaml` (`damage`), огнестрельное требует `ammo`, без оружия — кулаки
  `1d6−3`;
- граната до первого раунда (`2d6+1`), аптечка между раундами;
- единица `ammo` — коробка; по правилам книги после находки боеприпасов расход
  не считается; в бою показываются только имеющиеся weapon-предметы;
- лавка `scenes.*.shop` (ZombieBlood §329): покупка за `price`, списание `money`,
  выдача предмета и сохранение;
- враги с `count`, `health`, `attack`; урон по общему пулу HP;
- `on_enter` сцены применяется до боя (фиксированный урон, выдача предметов);
- продолжения после гранаты/первого залпа: `preDamage`, в том числе по списку
  предшественников (`preDamageFrom`);
- Зомби Конг: `threshold: 20` + бонус пистолета Эми `1d6+2`;
- §375: `preStamina: 6` до первого раунда;
- победа сохраняет Выносливость, инвентарь и переходит в `win`-сцену.

`lose` в книге не указан, поэтому поражение обрабатывается общим экраном смерти, а не
отдельной сценой. Непрерывность «оставшихся зомби» между сценами реализована через
повторный бросок `preDamage` в начале боя, а не через перенос точного остатка из
предыдущей сцены; это зафиксировано в `review.md` (`C_STAT_AMBIGUOUS`).

Проверены все 39 боёв, включая §17/§22/§158/§209/§256/§325/§357/§375 с
`preDamage`/`preStamina`/порогом. Основной сквозной тест — §45: 19 зомби,
пистолет-пулемёт, победа в §149; Выносливость и инвентарь сохраняются. Поражение,
повтор, стрелки/Enter и анимация броска проверены отдельно. Также проверены
лавка §329, выдачи §222/§235 и миграция старых сейвов для потерянных предметов.

## 4. Сохранения и `rev`

- Ключ сохранения: `quest:save:<id>`.
- В текущем MVP `rev` — отпечаток `story.md`. Правка сюжета инвалидирует старые
  сохранения; правка эффектов в `game.yaml` — нет.
- Если книга изменилась, предупреди игрока: старый сейв начнётся с начала.
- `on_enter` применяется при **входе** в сцену. Загрузка сейва сразу в сцену не
  является входом: эффект не применится. Для проверки ставь сейв на сцену-предшественник
  и делай выбор.
- POWER-перезапуск сбрасывает сцену, инвентарь и статы и проигрывает BOOK LOADER.

## 5. Известные ловушки

| Ловушка | Что делать |
|---|---|
| `use: [medkit]` | писать `use: medkit`; `[medkit]` — это id с скобками, `E_EFFECT_UNKNOWN_ID` |
| `items`/`stats`/`flags` без файла | убрать ключ; не создавать пустой файл |
| `items`/`stats`/`flags` есть, ключа нет | добавить ключ; иначе плеер не узнает о механике |
| `start_items` списком | MVP понимает только карту; используй `id: количество` |
| `drop` списком на выборе | MVP ждёт один id; список — только в `on_enter` |
| `set`/флаги | MVP применяет; проверь объявление в `flags.yaml` и сохранение в сейве |
| `stats.show` | MVP игнорирует; скрытие статуса не сработает |
| несколько `images` | MVP показывает только `image` |
| `###`/`**` в прозе | MVP показывает как plain text; переведи в обычный текст |
| `{stat: {money: -200}}` | парсить с учётом вложенных `{}`, иначе маркер попадёт в текст |
| `on_enter` в цикле | эффект повторится; перенеси на вариант или пометь `C_EFFECT_REPEAT` |
| `cover`/`illustrator`/`translator` | MVP не выводит; это не ошибка пакета |
| папка `my-book`, `id: other-book` | привести к одному значению; иначе сейвы/API расходятся |

## 6. Что не считать дефектом MVP

- `—` в авторе, жанре, аннотации или прогрессе;
- отсутствие кнопки инвентаря у книги без предметов;
- отсутствие кнопки характеристик у книги без `stats.yaml`;
- `ПУСТО` в инвентаре, если предметы ещё не найдены;
- `READY` с паузой ~0,4 с;
- скрытые подписи в `textContent` на мобильном;
- отсутствие музыки, если все `moods` равны `null`;
- `cover`, `illustrator`, `translator`, `status`, `theme` в пакете, но не в UI.

## 7. Минимальный чек-лист перед каталогом

```text
[ ] парсер: 0 ошибок
[ ] assets: все 200
[ ] id == папка
[ ] optional files: только при наличии
[ ] items/stats: меню соответствует данным
[ ] flags: set/if: flag; флаги в сейве
[ ] story: нет маркеров и Markdown-мусора
[ ] save: продолжение и сброс
[ ] POWER: BOOK LOADER и сброс
[ ] desktop + mobile portrait
[ ] book в библиотеке, первая сцена, концовка
```

Если пункт не проходит — пакет ещё не готов к передаче, даже если `review.md` закрыт.
