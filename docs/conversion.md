# Пошаговая конвертация книги

> Часть инструкции QuestRules. Точка входа — [AGENTS.md](../AGENTS.md).
>
> Алгоритм ИИ-конвертера: от текста книги до готового пакета.

## А.7. Конвертация книги-игры (справочно)

Проверено на «Стань стальной крысой!» Гарри Гаррисона (350 секций, 517 отсылок).

| Что в книге | Что в пакете |
|---|---|
| секция с номером | сцена `## 232`, `title: Глава 232` |
| `[253]` внутри фразы | фраза осталась в прозе, помечена тегом; `[А]` виден игроку, кнопка «Вариант А» |
| ровно одна отсылка | `next: "253"`, в интерфейсе кнопка «Далее» |
| две и более отсылки с условиями | `variants` в манифесте, фразы помечены тегами |
| «окажешься на [343] или на [342]» без критерия | `next.roll: 1d6`, `outcomes` 50/50 |
| секция без отсылок | `ending: true` |

Чего в пакете не будет: номеров в повествовании. «Тогда ты — на 232» — это адрес, а не
текст; он живёт в ключе сцены и в названии главы.

Проверка после конвертации: 350 сцен, 0 битых целей, 0 тупиков, 5 концовок; после
разметки по шагу 3 текст сцен совпадает с книжным — смысловые фразы не вырезаны.

### А.8. Инструкция для ИИ-конвертера

Алгоритм для разбора **любой** книги-игры. Шаги выполняются по порядку; результат
шага 10 — обязательное условие готовности.

**Критерий готовности:** пакет проходит валидатор без ошибок; после разметки по шагу 3
текст сцен совпадает с книжным (смысловые фразы не вырезаны); отчёт (шаг 11) приложен и
разобран с человеком (шаг 12).

#### Шаг 0. Зафиксировать источник

Перед секциями приводится в порядок сам файл: кодировка, PDF-колонтитулы, мусор
магазина, проверка полноты. Полный чек-лист — [source.md](source.md).

Итог шага: чистый текст плюс ответ на вопрос «полная книга или фрагмент».
Если найден фрагмент, разбор **останавливается**, и человек решает, продолжать ли
ознакомительным куском; при продолжении в манифесте ставится `status: fragment`, а
признак фрагмента фиксируется в отчёте как `C_SOURCE_FRAGMENT`.

#### Шаг 0.5. Определить тип книги

Тип определяет, какие правила и файлы применяются: `storybook`, `fighting-fantasy`,
`rpg` или `hybrid`. Признаки и порядок — [book-types/index.md](book-types/index.md).

- тип определяется по сигналам: лист персонажа, кубики, бои, проверки, опыт, коды;
- **тип подтверждает человек**, молча он не ставится;
- при `hybrid` — общий вопрос и запись `C_TYPE_HYBRID` по каждому спорному месту;
- тип записывается в `game.yaml`: `type: storybook`.

#### Шаг 1. Найти структуру секций

Ищи в порядке убывания надёжности:

1. строки, состоящие только из числа — `^\s*\d{1,4}\s*$`;
2. заголовки с числом — `^#+\s*(?:§|Глава|Секция)?\s*(\d+)`;
3. маркеры вида `N.` в начале абзаца;
4. разделители `***`, `---` с числом рядом.

Дополнительно:

- заголовок «Глава N» — такой же равноправный маркер, как число в отдельной строке;
- **номер страницы — не секция.** Признаки: стоит в колонтитуле, повторяется на
  каждой странице, не попадает в диапазон найденных ссылок. Такой номер
  отбрасывается; спорный случай — `C_SECTION_AMBIGUOUS`;
- пропуски в нумерации допустимы, но каждый фиксируется: это либо потерянная
  секция, либо признак фрагмента (шаг 0);
- последовательность маркеров проверяется на монотонность: `1, 2, 3, … N` без
  повторов и откатов. Сбитая последовательность — почти всегда номер страницы,
  принятый за секцию, или склеенные секции (`C_SECTION_AMBIGUOUS`);
- ключи — строки; числовой ключ в манифесте всегда в кавычках.

Если нумерации нет — разбей текст на смысловые эпизоды по абзацам и разрывам,
присвой id по порядку (`s001`, `s002`, …) и зафиксируй в отчёте, что структура
восстановлена, а не найдена.

#### Шаг 2. Извлечь отсылки

Собери все формы, встречающиеся в тексте:

| Форма | Пример |
|---|---|
| в скобках | `[229]`, `(229)`, `{229}` |
| после предлога | «на 229», «к 229», «см. 229», «стр. 229» |
| со стрелкой | `→ 229`, `-> 229`, `=> 229` |
| словесная | «отправляйся на двести двадцать девять», «к тридцатой главе» |
| словесная в скобках | «[НЕМЕДЛЕННО ОТПРАВЛЯЙСЯ К ТРИДЦАТОЙ ГЛАВЕ!]» |
| тире | `– 87`, `— 12`, `- 59` |
| тире и скобки | `– (99)` |
| параграф/глава словами | «перейдите к параграфу 29», «Смотри главу 19» |

Стиль `— (N)` (тире и скобки) — стандарт выгрузок quest-book.ru: отсылка
закрывает строку варианта, поэтому вся строка и есть клауза варианта, а не часть
абзаца.

**Если в PDF есть ссылки-аннотации, цель берётся из них.** `pdftohtml -xml`
отдаёт `<a href="…#N">`; это надёжнее текстового разбора и снимает вопрос «число
или отсылка». На «Купале» 307 из 307 целей совпали. Текстовый разбор ниже
остаётся для книг без аннотаций.

Стили в одной книге могут смешиваться. Правило: посчитать отсылки каждого стиля;
доминирующий — тот, что покрывает не меньше 90% отсылок. Сцены с остальными стилями
разбираются по одной и попадают в `review.md` как `C_REF_MIXED`. Если ни один стиль
не набирает 90%, книга считается смешанной: решение по каждой сцене, общий вывод —
в отчёт.

Отсылкой считается только то, что ведёт на существующую секцию: число, которого нет
среди секций, — **не** отсылка, а часть текста (год, возраст, сумма). Такие случаи
перечисли в отчёте.

**Проверка «что стоит после числа».** Настоящая отсылка стоит в конце фразы: за
числом идёт `.`, `,`, `;`, `!`, `?`, `»` или слово «Если»/«или». Если за числом
идёт строчное слово («в результате - 8 зомби убиты»), это не отсылка. На
ZombieBlood тест дал 0 ложных срабатываний на 614 отсылках — дешевле и точнее
любых эвристик по словарю.

**Диапазоны и записи бросков.** Число через тире — `1-3`, `1d6-3`, `2d6+1` — не
отсылка: в регулярном выражении нужен lookbehind `(?<![\w,])`, иначе диапазоны
дают десятки битых целей. Отдельно проверяются числа сразу после предлогов
(«на 1 очко», «за 10 долларов»): они отсылками не становятся.

Отсылки, записанные словами, требуют отдельного разбора: переведи слово в число,
проверь, что такая сцена существует, замени адрес на `[А]` (выбор) или удали адресную
формулу (линейный переход) и занеси случай в `review.md` с кодом `C_REF_WORDED` (§0.5,
[review.md](review.md)). Молча подставлять «первую попавшуюся» главу
нельзя — именно так пролог уводил в главу 1 вместо главы 30.

#### Шаг 3. Нормализовать текст

| Что | Как |
|---|---|
| кодировка | привести к UTF-8 |
| переводы строк | `\r\n` → `\n` |
| неразрывный пробел | `U+00A0` → обычный пробел |
| двойные пробелы | схлопнуть в один |
| «ё» | оставить как в источнике, не исправлять |
| пунктуация, орфография | **не трогать** |

Полнота переноса проверяется на шаге 10: текст после разметки по списку ниже совпадает
с книжным. «Разметка по шагу 3» далее означает ровно это: номер заменён на `[А]`
(выбор) либо удалён вместе с предлогом (линейный переход, бросок); чисто адресные
формулы и навигационные строки-действия удалены целиком; других изменений текста нет.

**Что именно удаляется из прозы.** Список разрешённых удалений закрытый, и для
каждого типа перехода он свой:

| Тип перехода | Что удаляется | Что остаётся |
|---|---|---|
| выбор | только цифры номера (вместо них `[А]` внутри тега) | тире, предлог, вся фраза; `[А]` — часть тега |
| линейный | номер с предлогом и «то»; если во фразе нет ничего, кроме адреса, — вся адресная формула («Тогда ты — на 47») | осмысленная часть фразы |
| линейный с навигационной строкой («продолжить — (N)», «далее — (N)») | вся строка целиком: в ней нет ничего, кроме команды перехода | ничего, строка не несёт содержания |
| бросок | номер с тире и «то» после диапазона | диапазон `1-3` и фраза |

**Метка-команда или осмысленная фраза?** Линейная строка с одним адресом удаляется
целиком, только если это команда: инфинитив или императив («Домой», «Прыгнуть»,
«Готовиться к празднику», «Найти колесо и катить его на берег»). Если в строке
нарратив или реплика, удаляется только адрес: «Вы осматриваете поляну — (145)» →
«Вы осматриваете поляну»; «- А зачем это, бабушка? — (215)» → «- А зачем это,
бабушка?». На «Купале» так удалено 105 строк и сохранено 6. Критерий — лицо и
наклонение, а не длина.

Удаление сверх этого списка — признак ошибки разбора. Другого списка нет: шаг 10
проверяет полноту ровно по этому перечню. Если после правки фраза читается плохо
(«Бросьте кубик. Если выпадет 1-3. Если выпадет 4-6.») — это `C_TEXT_FRAGMENT`, но
переписывать текст нельзя: случай идёт в отчёт.

#### Шаг 4. Построить граф

- узлы — секции, рёбра — отсылки;
- проверь: каждая отсылка ведёт в существующую секцию; если нет — это дефект
  источника, оставь сцену без ребра и отметь в отчёте;
- найди листовые узлы (без отсылок) — каждая такая сцена становится концовкой
  (`ending: true`);
- найди недостижимые из старта узлы — отметь, но не удаляй.

#### Шаг 5. Классифицировать переходы

| Признак в тексте | Решение |
|---|---|
| ровно одна отсылка | `next: sNNN` |
| вариант без адреса (буллет без номера, ссылка потеряна в источнике) | цель не выдумывается; фраза остаётся в прозе без тега; сцена ведёт `next` на единственную валидную цель или остаётся блокером; `C_REF_UNRESOLVED`, решение человека |
| ровно одна отсылка при слове-действии: «продолжить — (N)», «далее — (N)» | `next: sNNN`; строка удаляется целиком как навигационная (шаг 3) |
| одна ссылка с подписью «Концовка: X — (N)» | `next: sNNN`; подпись «Концовка: X» остаётся в прозе без адреса (метка ссылки, а не сцена) |
| две и более, при каждой есть условие или вопрос («если», «?», «решай», «как поступишь») | `variants` (набор вариантов) |
| две и более, но выбора нет: «или на [N]», «окажешься на [N] или [M]», «брось кубик» | `next.roll` + `outcomes` |
| две и более и в тексте явная случайность: «подбрось монету», «орёл/решка», ДОСП, кубик, жребий | `next.roll` + `outcomes` |
| две ссылки в одном абзаце с «если/или» | варианты, см. шаг 5.5 |
| «Если записано «N» – …» | выбор с условием по флагу `code_N` |
| «если ваше обаяние меньше трёх – 309, иначе – 292» | проверка характеристики (`checks`), не выбор |
| блок «АТАКА / ЗАЩИТА / ЖИЗНИ» рядом со ссылкой | бой (`combat`), не переход |
| отсылок нет | `ending: true` — у листовой сцены всегда; если финальной фразы (в том числе по смыслу) в тексте нет, ещё и `C_SCENE_DEAD_END` в отчёт |

**«<…>» — подпись «промолчать», а не пропуск.** Если у сцены это единственная
ссылка, строка навигационная и удаляется целиком (как «Домой — (N)»); если ссылок
две и более, `<…>` становится обычным вариантом (`{Б}<…> [Б]{/Б}`). В «Купале» все
53 такие строки были единственными и удалены.

Дублированная проза (один и тот же абзац с разными концами) — не две сцены, а одна
сцена с вариантами: см. [book-types/storybook.md](book-types/storybook.md). Слияние —
вариант, фиксируется `C_TEXT_DUPLICATE` и подтверждается человеком; без подтверждения
обе сцены остаются.

**Обёртка не значит ничего.** «Если выпадет орёл, ты на [37]» начинается с «Если», но
это не выбор игрока, а монета. Смотри на содержание, а не на союз: наличие
«Если…» само по себе не делает развилку выбором.

Правило сомнения: **если не уверен — выбирай варианты.** Кубик ставится только
тогда, когда в тексте нет решения игрока. Линейный переход никогда не превращается в
выбор из одного пункта.

**Порядок исходов броска.** `outcomes` проверяются сверху вниз, срабатывает первый
`бросок >= min`, поэтому исходы записываются **по убыванию `min`**: для
`1-2 → A`, `3-4 → B`, `5-6 → C` правильный порядок — `{min: 5}`, `{min: 3}`,
`{goto: A}`. Порядок по возрастанию — ошибка: бросок 5 уходит в ветку `3-4`
(это реальный баг конвертера ZombieBlood, поймано сверкой «бросок → сцена»).

Проверки броска, которые ставит самопроверка: покрытие `1…6` без дыр; `min`
строго по убыванию; исход без `min` ровно один и последний; каждый `goto`
существует.

#### Шаг 5.5. Выборы в прозе

Если отсылки стоят внутри абзаца (две и более), абзац делится на клаузы:

1. каждая ссылка завершает свою клаузу;
2. клауза остаётся в тексте сцены, оборачивается тегом `{А}…{/А}` и получает `[А]`,
   `[Б]`, … внутри тега;
3. подпись кнопки — буква (`Вариант А`); из прозы ничего не извлекается и не
   вырезается;
4. проверка («если ваше обаяние меньше трёх») не становится вариантом — шаг 5.6;
5. спорная клауза — `C_INLINE_CHOICE` в ревью.

Пример: «Если хотите позвать Отто - 59. Если предпочитаете подождать - 194.»
→ два варианта с подписями «Вариант А» и «Вариант Б»; обе фразы остаются в тексте
сцены, `[А]`/`[Б]` — внутри тегов.

**Четыре ловушки нарезки (проверено на 400 параграфах).**

1. **Пунктуация между клаузами — вне тега.** Запятая и точка принадлежат тексту
   перед тегом, иначе в рендере склеивается: `{/А}{Б}либо выйти` даёт
   «…,[Б]либо». Пробел перед `{Б}` тоже ставится в текст, а не в тег.
2. **Граница предложения учитывает закрывающую кавычку.** Разделитель — не
   только `. `, но и `!» `, `?» `, `.» `. Иначе тег захватывает чужую реплику
   («Ты один из них!» …).
3. **Союзы «либо»/«или» не режут клаузу.** В «Если у вас есть лом или меч, то
   вскрыть замок будет несложно» союз стоит внутри условия; разрез по нему
   отрывает «или меч» от фразы варианта.
4. **Вторая отсылка часто начинается с местоимения** («Если её у вас нет») — это
   тот же вариант, просто с отрицанием; см. [items.md](items.md), §«Проверки
   предметов в прозе».

**`<…>` и `<..>` — валидная подпись варианта.** Если такая строка стоит среди двух
и более ссылок, она остаётся в прозе как клауза и получает тег, как любой другой
вариант; подпись кнопки всё равно буква. Пустой клаузу она не делает и вырезать
её нельзя.

#### Шаг 5.6. Инвентаризация механик

До разметки сцен выписать всё, что книга считает: характеристики, навыки, деньги,
опыт, ресурсы, проверки, бои.

- числа и деньги → `stats.yaml` (деньгам — своё правило размещения списаний,
  [stats.md](stats.md) §8.1.1);
- предметы, оружие, расходники → `items.yaml`;
- проверки → `mechanics.yaml → checks`;
- бои → `mechanics.yaml → combat` (`count`, `attack`, `health`, `weapon`, `win`,
  при необходимости `preDamage`/`preStamina`/`threshold`);
- покупки в лавке → `scenes.*.shop`;
- что формат пока не выражает → `review.md` (`C_CHECK_UNSUPPORTED`,
  `C_COMBAT_UNSUPPORTED`, `C_ITEM_SHOP`, `C_MECHANICS`), текст не переписывается.

**Достижения** («Лист персонажа» с достижениями, «получено достижение «X»»,
«Если отмечено «X»: …»): это флаги, а не коды и не статы. `«X»` / «получено
достижение «X»» → `set: x` в `on_enter`; «Если отмечено «X»: …» → `if: flag x`;
два достижения через запятую — `flag a and flag b`. Каждый флаг должен иметь
выдачу и проверку; аудит флагов — как аудит предметов. Концовочные бейджи не
моделируются, если их никто не проверяет.

**Предметы инвентаризируются по трём графам:** где книга его **выдаёт** (цитата),
где **проверяет** (сцена и вариант) и где **тратит** (эффект). Итог — таблица
«Аудит предметов» в `review.md`; без неё модель предметов нельзя проверить
глазами (в ZombieBlood после аудита — 29 предметов, 50 take-эффектов и 18 проверяемых
id). Правила разбора проверок — [items.md](items.md); формат аудита —
[review.md](review.md).

**Выдача в `on_enter` повторяется.** Формат не знает «однократных» эффектов:
повторный вход в сцену с `take` выдаст предмет ещё раз. Это ограничение
фиксируется кодом `C_EFFECT_REPEAT`, а не замалчивается.

Правила по типам — [book-types/index.md](book-types/index.md).

#### Шаг 6. Разметить сцены

- ключ сцены — номер секции как строка (`232`) или слаг для авторских игр;
- заголовок `## 232`, в манифесте `"232":` — **числовой ключ в кавычках**;
- `title`: если у главы есть название — оно; если только номер — «Глава 232»;
- проза — только повествование: номеров и чисто адресных формул в ней нет; осмысленная
  фраза перехода остаётся и тегируется на шаге 7;
- служебная строка с номером в источнике в прозу не попадает: она уже стала ключом.

#### Шаг 7. Разметить переходы, сохранив фразы в тексте

Для каждой отсылки:

1. найди фразу (предложение или клаузу), в которой она стоит;
2. замени номер отсылки на букву: `[А]`, `[Б]`, `[В]`…;
3. оберни эту фразу целиком тегом `{А}…{/А}` **вместе с отсылкой `[А]`** — фраза
   остаётся в прозе, отсылка остаётся видимой и кликабельной;
4. подпись не придумывай: в интерфейсе кнопка называется `Вариант А`, `Вариант Б`, …
   (§4.5, [story.md](story.md)) — из текста ничего не вырезается и не пересказывается;
5. допиши цель в манифест: `variants: {А: "<ключ>", Б: "<ключ>"}`;
6. чисто адресные фразы без содержания («Тогда ты — на [76]», «Смотри на [76]»)
   удаляются целиком — это разрешённое удаление из шага 3; фраза с содержанием
   («Ты шагаешь внутрь, на [40]») остаётся, удаляется только адрес. Номер в прозе не
   остаётся ни в каком виде: `[232]` — такой же запрещённый остаток, как «на 232».

Устаревший способ — вырезать фразу и оставить её подписью — **запрещён** (§4.4, [story.md](story.md)).
Признак старого парсера: в тексте сцены появились дыры («…, и сразу повесил трубку»),
а подпись варианта существует отдельно от текста.

Правило проверки: текст сцены после разметки по шагу 3 должен совпадать с книжным.
Если после разметки фраза читается плохо — это `C_TEXT_FRAGMENT`, но удалять её нельзя.

Не помечай в `review.md` штатные переходы: предложения, начинающиеся с «Если»,
«Или», «Тогда», «В этом случае», — ожидаемая навигация, их фразы остаются в тексте и
получают тег. В отчёт попадают только случаи, где разметка неоднозначна.

#### Шаг 8. Заполнить метаданные

| Поле | Когда заполнять |
|---|---|
| `author`, `genre`, `annotation` | для карточки в библиотеке: автор и жанр — из книги, аннотация — из предисловия/первой фразы. Нет данных — поле не пиши, интерфейс покажет прочерк |
| `title` | всегда. Если в книге названий нет, ставится «Глава N». Если человек просит придумать названия — это добавление контента: черновик берётся из первой фразы (до 40 символов, без висящих союзов), помечается `C_CONTENT_ADDED` и требует вычитки человеком |
| `ending` | всегда у листовой сцены (без `next` и `variants`); если финальной фразы (в том числе по смыслу) в тексте нет — случай в `review.md` как `C_SCENE_DEAD_END` |
| `next` | по шагу 5 |
| `roll`/`outcomes` | по шагу 5 |
| `mood` | всегда: у каждой сцены есть `mood`; `null` значит «настроение есть, трека нет»; список — по `soundtrack.md` |
| `image` | только из плана `illustrations.md` и только с цитатой-доказательством; нет цитаты или файла — поле не ставится |
| `on_enter`, `take`, `use`, `drop`, `set`, `stat` | только если книга **явно** предписывает изменить состояние |
| `items.yaml`, `stats.yaml`, `flags.yaml` | только если книга требует учёта; иначе файлов нет |
| `type` | всегда: `storybook`, `fighting-fantasy`, `rpg` или `hybrid` |
| `status` | всегда: `complete` или `fragment` (см. шаг 0) |
| `cover` | если есть обложка: путь к файлу, раздел «Обложка» в [metadata.md](metadata.md) |
| `illustrator`, `translator`, `edition`, `year`, `source` | из книги и выходных данных; нет данных — поле не пишется ([metadata.md](metadata.md)) |
| `mechanics.yaml` | если найдены проверки или бои (шаг 5.6) |

`genre` — это жанр, а не формат: не дублируй в нём «книга-игра», для этого есть `type`.
Если из книги кроме «книга-игра» ничего не следует, поле не пиши.

Запрещено: вводить предмет за упоминание в прозе, делать статус из очков, которые
книга предлагает «запоминать», добавлять эффекты «для интереса».

Если предметы есть в вариантах, но проверок нет — не решай сам, тратить ли предмет и
ставить ли `if: has_item`: оставь безопасное поведение (не тратит, не блокирует) и
занеси случай в `review.md` с кодом `C_ITEMS_UNTRACKED` (§0.5, [review.md](review.md)).

**Если книга проверяет предмет — это условие, а не украшение.** «Если у вас есть
лом - 185. Если его у вас нет - 300» — пара вариантов, на первый ставится
`if: has_item crowbar`, на второй — `if: not has_item crowbar`. Три правила,
без которых модель ломается (подробно — [items.md](items.md)):

- **местоимение относится к предмету из предыдущей клаузы;** отрицание `or`-цепочки
  оборачивает всю цепочку: `not (has_item a or has_item b)`;
- **проверяемый предмет должен иметь источник** в книге. Нет источника — условие не
  ставится (иначе ветка недостижима), случай идёт в отчёт как `C_ITEM_NO_SOURCE`;
- **предмет из свободной лавки** («купите, что хотите, за доллар») не выдаётся
  эффектом: покупку формат не выражает — `C_ITEM_SHOP`, проверки не блокируются.

- `story.md` — сцены по шагу 6 в размеченном виде: `{А}…{/А}`, `[А]`, строки
  `Вариант А`; цели — в `variants` манифеста;
- `storyGraph.md` — карта ветвлений по (§2.3, [story-graph.md](story-graph.md)): таблицы выходов, концовки, хабы,

- `illustrations.md` — по [illustrations.md](illustrations.md): кадры, а не области; у каждого кадра цитата-доказательство,

Кодировка UTF-8, имена ASCII.

#### Шаг 9.1. Как выбирать настроение

Правила и ориентиры — в [soundtrack.md](soundtrack.md). Порядок работы:

1. Найди **цитату** в тексте сцены, которая задаёт атмосферу: угроза, тишина, погоня,
   находка, потеря. Цитата пойдёт в бриф и должна быть дословной подстрокой текста;
2. По цитате выбери настроение из закрытого списка: `calm`, `tense`, `danger`,
   `victory`, `mystery`, `grief`. Новый ключ не выдумывай;
3. Нет сильной цитаты — поставь настроение по нейтральной фразе сцены и занеси случай в
   `review.md` как `C_MOOD_NO_EVIDENCE`; `mood` не оставляй пустым;
4. Запиши настроение в `game.yaml → scenes.<ключ>.mood` и строку с цитатой в
   `soundtrack.md` — эти две записи обязаны совпадать (`C_MOOD_MISMATCH`);
5. Проверь распределение: настроений не больше 6 (весь закрытый список), для короткой
   книги меньше — если у каждой сцены есть цитата; соседние сцены по возможности делят
   одно;
6. Настроение без трека объявляй как `null` и заноси в `review.md`
   (`C_MOOD_TRACK_MISSING`): сцена с таким настроением продолжит текущую музыку.

#### Шаг 9.2. Как выбирать кадр

Если в книге уже есть иллюстрации, кадры не придумываются: включается режим
«Иллюстрации из книги» ([illustrations.md](illustrations.md)) — извлечение, привязка
к сценам, обложка. Придуманные кадры остаются для сцен без книжных рисунков.

1. Найди «свою» клаузу ([illustrations.md](illustrations.md), этап 1): где герой и что он делает. Нет места и действия —
   сцена остаётся без кадра, и это нормальный результат, а не пробел в работе;
2. Выпиши **цитату** — дословный фрагмент этой клаузы. Цитата идёт в бриф и будет
   проверена как подстрока текста сцены (этап 5);
3. Сформулируй кадр: место + действие + кто в кадре. «Лес» — место, а не кадр;
   «герой у костра в лесу» — кадр;
4. Сцены с одинаковым кадром (то же место и то же действие) получают один номер;
   сцены с разным действием в одном месте — разные кадры, даже если местность одна;
5. Приоритет: `высокий` — пролог, первые сцены, концовки, ключевые повороты;
   `средний` — обычные сцены; `низкий` — проходные;
6. Наследование — только по рёбрам графа и только при отсутствии своих признаков
   ([illustrations.md](illustrations.md), этап 4). Наследовать кадр от сцены с номером N−1 запрещено;
7. Прогони проверку этапа 5. Если кадр поставлен без цитаты или цитата не находится в
   тексте сцены — `C_ILLUSTRATION_NO_EVIDENCE`: либо найди цитату, либо сними кадр;
   спорный кадр — `C_ILLUSTRATION_AMBIGUOUS`; топоним вне словаря мест —
   `C_ILLUSTRATION_TOPO_UNKNOWN`;
8. Не описывай то, чего нет в тексте: придуманный кадр — `C_CONTENT_ADDED`;
9. Проверь масштаб: 350 сцен и 14 картинок — это разметка по областям, а не по кадрам.
   Кадров должно быть столько, сколько разных мест и действий в книге;
10. Пролог, интерлюдии и концовки — `высокий` приоритет. Если места действия нет,
    ищи контекст в тексте: учреждение, транспорт, помещение («в главном здании
    Корпуса») — этого хватает для установочного кадра (этап 3.1 в
    [illustrations.md](illustrations.md));
11. Сверь каталог файлов в обратную сторону: каждый файл либо привязан к кадру, либо
    помечен как неиспользуемый с причиной (этап 6). Готовый файл без кадра — это
    потерянная иллюстрация, а не мелочь.

#### Шаг 11. Собрать `review.md`

Каждое сомнение — строка в таблице по (§0.5, [review.md](review.md)). Сводка сверху: число сцен, переходов и
открытых пунктов.

- не решай молча: лучше лишняя строка в отчёте, чем незамеченная ошибка;
- в спорном месте принимай безопасное решение по умолчанию и продолжай — конвертация
  не останавливается;
- по завершении просмотри файл целиком: если строк стало больше двух десятков, ищи
  системную причину в шагах 1–7, а не разбирай каждую по отдельности;
- приёмка: `open` = 0.

Отчёт — часть результата. Пакет без `review.md` считается непроверенным.

#### Шаг 11.1. Аннотированный исходник

Для новых книг шаги 7–8 заменяются разметкой по (§2.2, [story.md](story.md)): варианты получают буквы `[А]`,
`[Б]`, фрагменты прозы оборачиваются в `{А}…{/А}` вместе с отсылкой, строки `Вариант А` несут
модификаторы, цели лежат в `variants` манифеста. Разбор выполняет парсер, подписи из
прозы не извлекаются.
Старые шаги 7–8 остаются для книг, размеченных только номерами; шаг 9 (сборка файлов)
не меняется.

#### Шаг 12. Пройти `review.md` вместе с человеком

Пакет собран — работа ещё не закончена. ИИ сам открывает диалог по отчёту, не дожидаясь,
пока человек его прочитает и придёт с вопросами.

Когда отчёт разобран и человек подтвердил пакет, только тогда файлы передаются дальше —
в движок или в каталог готовых игр. До подтверждения пакет остаётся в каталоге книги:
ревизия пользователем обязательна, а не опциональна.

1. Сгруппируй открытые пункты по коду: один код — один вопрос о правиле, а не N вопросов
   о каждом случае.
2. Для каждого пункта покажи: сцену и фрагмент, что сделано по умолчанию, 2–4 варианта
   решения, рекомендацию и последствия каждого варианта.
3. Задавай вопросы пакетами (до четырёх за раз), а не по одному.
4. Записывай ответ сразу в `review.md`: статус `ok` (принято как есть), `fixed`
   (данные изменены) или `wontfix` (человек отказался менять), а в «Что проверено» —
   формулировку решения.
5. Если решение меняет данные — пересобери затронутые файлы и повтори самопроверку
   (шаг 10).
6. Не оставляй `open` без явного отказа человека: пока есть `open`, пакет не готов
   к приёмке; отказ фиксируется статусом `wontfix`.

**Чего не делать:** не спрашивать о том, что уже решено в предыдущих пунктах; не
переспрашивать одно и то же правило дважды; не прятать своё мнение за «как скажешь» —
рекомендация обязательна, человек её корректирует.

#### Шаг 13. Передать пакет в плеер

Пакет прошёл `review.md` — но это ещё не проверка интерфейса. Перед каталогом готовых
книг пройди preflight из [handoff.md](handoff.md). Минимум:

- [ ] целевой парсер открывает пакет с 0 ошибок;
- [ ] `items`/`stats` объявлены только при наличии файлов; меню в плеере соответствует
      данным (у книги без предметов кнопки инвентаря нет);
- [ ] все ассеты отдаются `200`, `id` совпадает с папкой;
- [ ] библиотека показывает книгу, автор/жанр/аннотация не ломают карточку;
- [ ] BOOK LOADER доходит до первой сцены, `.parse-report` отсутствует;
- [ ] первые выборы, иллюстрация и концовка проходятся;
- [ ] сохранение продолжает сцену, сброс и POWER-перезапуск работают;
- [ ] мобильный портрет: иконки, скрытые подписи, нет горизонтального скролла;
- [ ] известные ограничения плеера (`start_items` списком, `set`, `flags`,
      `mechanics`, `stats.show`, несколько `images`) не используются без поддержки.
- [ ] если сюжет держится на флагах — целевой плеер применяет `set` и `if: flag`;
      иначе книга схлопывается (см. [handoff.md](handoff.md) §3.5).

Если пункт не проходит — это дефект передачи, а не «мелкая вёрстка». Не передавай
пакет в каталог, пока он не открывается как пользовательская книга.

#### Типичные ошибки

| Ошибка | Почему плохо |
|---|---|
| переписанный текст | убивает сверку и авторский голос |
| линейный переход, ставший выбором | игрок «выбирает» то, чего не выбирал |
| кубик, заменённый выбором | игрок получает контроль над случайностью |
| выбор, заменённый кубиком | теряется решение игрока |
| придуманные предметы и статусы | расходится с книгой, ломает баланс |
| удалённые «неудобные» ветки | теряется часть истории |
| отсылка, принятая за число | появляются битые цели |
| кадр по слову из цитаты, стиха или чужого действия | картинка не о том месте, и ошибка не видна автору |
| наследование кадра от сцены N−1 | картинка соседней ветки выдаётся за текущую сцену |
| топоним, подогнанный под «похожее» место | «деревенька» становится лесом или городом без основания |
| фрагмент, разобранный как полная книга | игрок упирается в обрыв там, где книга продолжается |
| тип книги, поставленный молча | правила не того типа уродуют пакет |
| смешанный стиль отсылок, разобранный «как получится» | часть ссылок теряется, часть превращается в мусор |
| проверка, превращённая в выбор | игрок «выбирает» исход броска характеристики |
| дублирующаяся проза, записанная дважды | книга «толстеет», а игрок читает одно и то же |
| исходы броска по возрастанию `min` | бросок 5 попадает в ветку «3-4», исходы перепутаны |
| тег, начатый с запятой или точки | в рендере склеиваются соседние клаузы |
| условие, приклеенное к случайной клаузе | «если хотите снять крышку ящика» требует патронов |
| проверка на предмет без источника | ветка недостижима, игрок не может её выбрать |
| `use: [medkit]` вместо `use: medkit` | плеер ищет предмет с id `[medkit]` и падает на `E_EFFECT_UNKNOWN_ID` |
| пустой `items.yaml` без ключа `items` | файл не нужен, а ключ без файла даёт 404 или «механику без данных» |
| `###`/`**` в прозе при plain-text плеере | игрок видит решётки и звёздочки вместо заголовка |
| `{stat: {money: -200}}` разобран по первой `}` | остаток маркера попадает в текст сцены |
| `start_items` списком в MVP | плеер ждёт карту `id: количество`; список теряет предметы |
| `id` не совпадает с папкой | библиотека, API и сейвы расходятся, прогресс не находится |
| `cover`/`translator` заполнены, а UI их не показывает | это ограничение плеера, а не повод удалять провенанс |
| покупка в свободной лавке, выданная `take` | предмет появляется «за так» и ломает баланс |
| выдача в `on_enter`, прочитанная как однократная | повторный вход выдаёт предмет второй раз |
