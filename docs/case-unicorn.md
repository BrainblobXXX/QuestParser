# Разбор «Клетки Единорога»: минимальный storybook

> Часть инструкции QuestRules. Точка входа — [AGENTS.md](../AGENTS.md).
>
> Практика: короткая книга-игра без механик. Дополняет
> [case-zombieblood.md](case-zombieblood.md) (механик слишком много) и
> [case-2500.md](case-2500.md) (деньги без механик). Здесь — третий полюс: **нечего
> моделировать, и это нормально**.

## 1. Источник в цифрах

| Что | Значение |
|---|---|
| сцен | 16 |
| концовок | 5 |
| иллюстраций | 3 |
| предметы | нет |
| статусы | нет |
| флаги | нет |
| музыка | нет |
| тип | `storybook` |
| старт | сцена `1` |

Книга короткая и полностью проходимая: 16 сцен и 5 финалов. Ни одного предмета,
который проверяется условием, ни одной характеристики, которая меняется эффектом,
ни одного флага. Это не «недоразобранная» книга, а честный `storybook` без механик.

## 2. Что сработало и стоит повторять

- **Не выдумывать механику ради интерфейса.** Соблазн добавить `stats: money: 0` или
  пустой `items.yaml`, чтобы «кнопки появились», — ошибка. Кнопки появляются от данных,
  а не наоборот. Отсутствие меню здесь — правильный результат.
- **Короткая книга — отдельный тест на аккуратность.** 16 сцен проходятся целиком;
  потерянная фраза или лишний выбор сразу заметны.
- **Концовки по смыслу.** Ни в одном финале нет слова «конец»; `ending: true` ставится
  по смыслу, а не по формальной фразе. Пять финалов проверяются обходом.
- **Три иллюстрации с цитатами.** Каждая картинка привязана к сцене; сцена без кадра
  остаётся без `image`. Это лучше, чем «похожая» картинка.
- **Линейные фразы остаются в прозе.** «В сад!» и подобные фразы не обязаны
  превращаться в выбор: если выбора нет, сцена получает `next`.

## 3. Где правила пришлось уточнить

### 3.1. Отсутствие механик — валидный профиль

`storybook` не требует ни `items.yaml`, ни `stats.yaml`, ни `flags.yaml`. Если в книге
нет проверок и изменений состояния:

- не заводи пустые файлы;
- не добавляй `items`/`stats` в манифест;
- не добавляй эффекты `take`/`stat` «для интереса»;
- не считай отсутствие кнопок инвентаря/характеристик дефектом.

Проверка: в шапке книги остаётся только `MD`; на мобильном — только иконка `<>`.
Это ожидаемое поведение, а не потеря функциональности.

### 3.2. `genre` — не `type`

В исходнике жанр фактически «книга-игра». Это не жанр, а формат. Если из книги не
следует ничего кроме «книга-игра»:

- `type: storybook` уже описывает формат;
- `genre` лучше не писать, чем дублировать тип;
- если нужен жанр, бери его из обложки/аннотации: «тёмная сказка», «фэнтези»;
- UI может очищать суффикс «книга-игра»; не полагайся на это как на нормализацию.

### 3.3. Markdown-подзаголовок попал в текст

В сцене с правилами стоял `### Сражения`. Плеер MVP показывает прозу как plain text,
поэтому решётки остались на экране. Уточнение:

- `###` и глубже — допустимая Markdown-разметка пакета, но **не гарантия рендера**;
- если целевой плеер не поддерживает Markdown, замени подзаголовок обычным текстом
  или абзацем;
- случай фиксируется как `C_MARKDOWN_UNRENDERED`;
- проверяй не только `###`, но и `**`, списки, `code`, цитаты.

### 3.4. Аннотации нет — это допустимо

`annotation` в исходнике отсутствует. Поле не выдумывается: библиотека покажет `—`.
Это не ошибка книги и не повод пересказывать первый абзац «для красоты». Если человек
хочет аннотацию — это добавление контента, а не автопересказ.

### 3.5. Пять концовок без слова «конец»

Финальность читается по смыслу: герой остаётся, герой уходит, герой погибает и т.п.
Все пять сцен помечены `ending: true`; `C_SCENE_DEAD_END` не ставится. Отсутствие
формальной фразы — не повод добавлять «КОНЕЦ» в текст.

## 4. Маршрут для проверки

```text
1. Запустить книгу (сцена 1).
2. Enter: 1 → 2.
3. «1»: 2 → 12.
4. «1»: 12 → 8 — сцена с иллюстрацией.
```

Что проверить:

- только `MD`, без характеристик и инвентаря;
- картинка на сцене 8 открывается и закрывается;
- на мобильном — иконки, скрытые подписи, отсутствие горизонтального скролла;
- в концовке нет выбора и нет «СБОЙ: ТУПИК»;
- нет `.parse-report`;
- библиотека показывает жанр/тип без «книга-игра».

## 5. Чек-лист конвертера

- [ ] тип `storybook` подтверждён человеком;
- [ ] нет `items.yaml`/`stats.yaml`/`flags.yaml`, если механик нет;
- [ ] нет `start_items`;
- [ ] 16 сцен, 5 концовок, 3 `image` с цитатами;
- [ ] нет Markdown-артефактов в прозе (или они допустимы для целевого плеера);
- [ ] `genre` не дублирует `type`;
- [ ] каждая концовка достижима;
- [ ] UI smoke: только `MD`, скрытые меню, мобильная вёрстка.

## 6. Что осталось открытым

- жанр в исходнике фактически отсутствует; «тёмная сказка» — рабочее значение, а не
  цитата из книги;
- аннотации нет; поле остаётся пустым до решения человека;
- иллюстраций всего 3 на 16 сцен; это не ошибка, а особенность издания.
