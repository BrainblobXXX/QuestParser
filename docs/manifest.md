## 2. TBD 1. Структура игрового пакета

**Статус:** закрыт в 0.7.

**Решение.** Пакет — это папка (на этапе 2 — zip с папкой). Обязательных файлов два:

| Файл | Назначение |
|---|---|
| `game.yaml` | манифест: единственное место, где объявлены метаданные игры и сцен |
| `story.md` | все сцены пакета |

Опциональные:

| Файл / папка | Назначение |
|---|---|
| `items.yaml` | предметы (TBD 6) |
| `stats.yaml` | статусы (TBD 7) |
| `flags.yaml` | флаги (TBD 7) |
| `storyGraph.md` | карта ветвлений: выходы сцен, концовки, хабы, Mermaid-граф (§2.3, [story-graph.md](story-graph.md)) |
| `review.md` | сомнительные случаи для человека (§0.5, [review.md](review.md)) |
| `theme.yaml` | тема оформления; в MVP не используется, TBD 9 |
| `assets/` | изображения и звук; пути только относительные от корня пакета |
| `soundtrack.md` | бриф композитору: настроение каждой сцены и главы по настроению; движок не читает |
| `illustrations.md` | бриф художнику: что нарисовать и к каким сценам; движок не читает |

Поля `game.yaml`:

```yaml
format: quest/1        # версия формата, обязателен
id: koshchei-cave      # ASCII-слаг, обязателен
title: Кощеева пещера
author: Гарри Гаррисон # для карточки в библиотеке; нет — прочерк
genre: фантастика · книга-игра   # свободная строка; нет — прочерк
annotation: Краткое описание книги для библиотеки, 1–3 предложения.  # нет — прочерк
language: ru
start: cave_entry      # id стартовой сцены, обязателен
story: story.md        # по умолчанию story.md
items: items.yaml      # опционально, по умолчанию items.yaml
start_items:           # с чем игрок начинает; id из items.yaml
  sword: 1             # можно списком — тогда количество 1
  sleep_grenades: 2
stats: stats.yaml      # опционально, по умолчанию stats.yaml
flags: flags.yaml      # опционально, по умолчанию flags.yaml
moods:                 # настроения сцен: ключ → трек, список треков или null
  calm: assets/audio/calm.ogg
  tense: assets/audio/tense.ogg
  mystery: null        # настроение размечено, трека пока нет
default_mood: calm     # только для сцен, у которых mood не задан вовсе
theme: theme.yaml      # только этап 2, TBD 9
scenes:                # метаданные сцен, см. TBD 2
  cave_entry:
    title: Вход в пещеру
```

**Настроения.** `null` у настроения значит «размечено, музыки нет»: сцена с таким
настроением продолжает текущий трек. `default_mood` подхватывает только сцены, у которых
`mood` отсутствует совсем. Подробно — [soundtrack.md](soundtrack.md).

**Карточка книги.** `title`, `author`, `genre`, `annotation` показываются на экране
библиотеки. `author`, `genre` и `annotation` необязательны: если поля нет, интерфейс
печатает прочерк. Ничего не выдумывай: автора и жанр бери из книги, аннотацию —
из предисловия или первой фразы, помечая пересказ в `review.md` (`C_CONTENT_ADDED`).

**Правила:**

- кодировка всех файлов — UTF-8; другая кодировка — ошибка валидатора;
- имена файлов и папок — ASCII, без пробелов;
- ссылки на ассеты только относительные и внутри пакета; `..`, абсолютные пути и
  внешние URL — ошибка;
- `format` обязателен: пакет без версии формата не запускается;
- `start_items` — стартовый инвентарь: список id (количество 1) или отображение
  `id: количество`; каждый id обязан быть объявлен в `items.yaml`, иначе ошибка. Поле нужно потому, что книжный герой почти всегда «уже вооружён», и без
  него предметы появляются только эффектами `take`;
- в MVP пакеты берутся из предзагруженного источника, но структура должна быть такой,
  чтобы тот же пакет принимался загрузкой этапа 2;

## 5. TBD 4. Условия

**Статус:** закрыт в 0.8.

**Решение.** Условие — строка с префиксными предикатами. Ключевые слова латиницей в
нижнем регистре, идентификаторы — те же слаги, что везде в формате.

```text
has_item rusty_key
flag door_open
stat hp <= 3
has_item rusty_key and not flag door_open
(stat hp < 5 or flag desperate) and has_item potion
```

**Грамматика:**

```text
expr      := or
or        := and ("or" and)*
and       := unary ("and" unary)*
unary     := "not" unary | "(" expr ")" | predicate
predicate := "has_item" ID | "flag" ID | "stat" ID CMP INTEGER
CMP       := "=" | "==" | "!=" | "<" | "<=" | ">" | ">="
```

**Семантика:**

- `has_item x` — предмет `x` есть в инвентаре: для считаемого это количество больше нуля;
- `flag x` — флаг `x` установлен; неустановленные флаги ложны;
- `stat x <оп> N` — сравнение числового статуса с целым числом;
- приоритет: `not`, затем `and`, затем `or`; скобки меняют порядок;
- `=` и `==` — одно и то же.

**Ошибки валидатора:**

- неизвестный предикат;
- неизвестный идентификатор предмета, флага или статуса;
- нецелое число в сравнении;
- незакрытая скобка или оборванное выражение — с указанием позиции;
- пустое условие (`if:` без значения); если условия нет — ключ `if` не пишется.

**Не поддерживается в MVP:** условия на сцене (только на выборах), проверка посещённых
сцен (`visited`), счётчики и вычисляемые значения внутри условий. `visited` отложен
до этапа 3.

## 6. TBD 5. Эффекты

**Статус:** закрыт в 0.8.

**Решение.** Эффект — пара `key: value`, где ключ задаёт глагол. Состав закрыт, другие
глаголы не поддерживаются.

| Ключ | Значение | Смысл |
|---|---|---|
| `take` | id, список id или `{id: количество}` | добавить предмет (по умолчанию 1) |
| `use` | id | применить предмет: уменьшить количество или убрать |
| `drop` | id или список id | выбросить предмет целиком |
| `set` | id или список id | установить флаг |
| `stat` | отображение id → целое | изменить статус на дельту |

**Порядок применения:**

- модификатор выбора — слева направо, как записан; внутри списка — по порядку элементов;
- при переходе: сначала эффекты выбора, затем `on_enter` целевой сцены;
- `on_enter` срабатывает при **каждом** входе в сцену, включая повторный;
- `on_enter` записывается в `game.yaml` как YAML-последовательность:

```yaml
scenes:
  cave_hall:
    on_enter:
      - set: entered_hall
      - stat: {hp: -1}
```

**Семантика:**

- у несчитаемого предмета (`countable: false`) `take` уже имеющегося не создаёт дубликат,
  а у считаемого — прибавляет количество;
- `use` уменьшает количество на 1 у расходника и убирает одноразовый предмет; на
  многоразовом предмете `use` запрещён;
- `drop` отсутствующего предмета — no-op в рантайме; предупреждение валидатора, если
  предмет не выдаётся ни в одном месте пакета;
- `set` уже установленного флага — no-op; снятие флага в MVP не поддерживается
  (вместо этого вводится второй флаг);
- `stat` прибавляет дельту к текущему значению и обрезает результат по диапазону
  статуса (диапазон — TBD 7); дельта `0` — ошибка валидатора;
- эффекты статичны: условных эффектов и вычисляемых выражений нет, ветвление — только
  через выборы и сцены (§1.2, [AGENTS.md](../AGENTS.md)).

**Ошибки валидатора:** неизвестный ключ, неизвестный предмет/флаг/статус, нецелая
дельта, эффект в месте, где он не поддерживается.

**Не поддерживается в MVP:** снятие флага (`clear`), одноразовые эффекты (`once`),
эффекты с условием, эффекты при выходе из сцены.

## 10. TBD 9. Тема оформления: отложен

**Статус:** решение отложено до этапа 2 (функциональное демо). В 0.10 тема сознательно
не фиксируется.

Что уже понятно:

- тема подчиняется (§1.2, [AGENTS.md](../AGENTS.md)): авторы не пишут CSS;
- тема — необязательный `theme.yaml`, только токены из белого списка;
- в MVP пакет тему **не задаёт**: движок использует одну встроенную базовую тему;
- критерий MVP «тема применяется» трактуется как встроенная тема ([MVP.md](../MVP/MVP.md), §5 п. 13);
- на этапе 2 решается набор токенов, проверка контраста и нужны ли пресеты.

Вопросы к решению на этапе 2:

- список токенов: цвета, шрифты, ширина колонки, отступы, фон;
- допустимые значения: hex-цвета, встроенные шрифты, без загрузки шрифтовых файлов;
- проверка контраста text/background как предупреждение валидатора;
- частичная тема: незаданные токены берутся из базовой;
- нужны ли готовые пресеты (`light`, `dark`, `parchment`) вместо ручных токенов.

## 11. TBD 10. Валидатор: ошибки и предупреждения

**Статус:** отложен до разработки демо. Политика, формат сообщений и глубина
проверки проходимости сознательно не фиксируются в 0.11.

### 11.1. Что отложить нельзя

Без этих проверок MVP не может разобрать игру и выполнить переход — они обязательны
независимо от того, каким будет полный каталог:

| Код | Почему обязателен |
|---|---|
| `E_PKG_NO_MANIFEST`, `E_PKG_MISSING_STORY` | нечего разбирать |
| `E_PKG_FORMAT_MISSING`, `E_PKG_FORMAT_UNSUPPORTED` | неизвестная версия формата |
| `E_PKG_PATH_ABSOLUTE` | выход за пределы пакета |
| `E_SCENE_NO_META`, `E_SCENE_META_ORPHAN` | иначе неясно, где чьи метаданные |
| `E_SCENE_DUPLICATE`, `E_SCENE_ID_INVALID` | иначе переход неоднозначен |
| `E_SCENE_START_MISSING` | игру невозможно начать |
| `E_CHOICE_TARGET_MISSING` | переход в пустоту |
| `E_CHOICE_UNKNOWN_KEY`, `E_EFFECT_UNKNOWN_KEY` | движок не знает, что исполнять |
| `E_COND_UNKNOWN_ID`, `E_EFFECT_UNKNOWN_ID` | опечатка ломает логику молча |
| `E_ASSET_MISSING` | картинка или музыка не загрузится |
| `E_MOOD_UNKNOWN` | настроение сцены не объявлено в `moods`, музыка не заиграет |

| `E_CHOICE_UNKNOWN_KEY` | E | неизвестный ключ модификатора |
| `E_CHOICE_EMPTY_TEXT` | E | пустой текст выбора |
| `E_LINK_VALUE_EMPTY` | E | пустая подпись перехода |
| `E_KEY_FORMAT` | E | ключ не номер главы и не слаг |
| `E_KEY_UNQUOTED` | E | числовой ключ в манифесте без кавычек |
| `E_NAV_IN_PROSE` | W | в прозе осталась навигационная фраза |

| `E_EFFECT_STAT_NONINT` | E | дельта не целая |

предметов не хватило») может быть недостижим по графу и при этом полезен как защита от
будущих правок. В книгах встречаются и страницы-сироты: сцены, на которые не ведёт ни
одна ссылка. И то и другое допустимо, если человек подтвердил случай в `review.md`;
удалять или пришивать такие сцены автоматически нельзя.

### 11.3. Открытые вопросы к этапу демо

1. **Политика предупреждений:** запуск разрешён или предупреждения тоже блокируют?
   Варианты: разрешён и показываются; блокируют; показываются только автору.
2. **Формат сообщения:** стабильный код + человеческий текст; только текст; код без текста.
3. **Глубина проверки проходимости:** только висячие ссылки; граф достижимости сцен и
   концовок; полный перебор с учётом условий (решатель).
4. **Где показывать:** экран ошибки перед запуском игры (MVP §2.1 п. 19) или отдельный
   «отчёт валидатора» в интерфейсе.
5. **Язык сообщений:** русский в MVP, английский — после локализации интерфейса.

### А.1. `game.yaml`

```yaml
format: quest/1
id: koshchei-cave
title: Кощеева пещера
language: ru
start: cave_entry
story: story.md
items: items.yaml
stats: stats.yaml
flags: flags.yaml
scenes:
  cave_entry:
    title: Вход в пещеру
    image: assets/images/cave-entry.jpg
    music: assets/audio/cave.mp3
    variants:
      А: cave_hall
      Б: cave_walls
  cave_walls:
    title: Стены
    variants:
      А: cave_hall
      Б: cave_entry
  cave_hall:
    title: Зал
    music: assets/audio/hall.mp3
    variants:
      А: cave_end_rich
      Б: cave_end_poor
    on_enter:
      - stat: {hp: -1}
  cave_end_rich:
    title: Богатая добыча
    ending: true
  cave_end_poor:
    title: С пустыми руками
    ending: true
```

### А.5. Что проверяет пример

- семь сцен в одном файле, id берутся из заголовков `##`;
- метаданные сцен — только в `game.yaml`, расхождение с заголовками ловит валидатор;
- две концовки помечены `ending: true`, тупиков нет;
- `cave_walls` возвращает назад — цикл не считается ошибкой;
- выбор «Открыть сундук» скрыт, пока нет ключа, и исчезает после первого открытия (флаг);
- предмет выдаётся эффектом на выборе, а не отдельной сценой-прокладкой;
- `stat` на входе в зал показывает дельту и обрезку по `min`;
- картинка и музыка заданы только у части сцен — они опциональны;
- все предметы, статусы и флаги объявлены в своих файлах, поэтому опечатка в любом
  идентификаторе — ошибка, а не тихо созданная сущность.
