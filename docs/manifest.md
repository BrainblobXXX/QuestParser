# Манифест игры: `game.yaml`

> Часть инструкции QuestRules. Точка входа — [AGENTS.md](../AGENTS.md).
>
> Структура пакета, поля манифеста, условия, эффекты, тема, проверки.

## 2. TBD 1. Структура игрового пакета

**Статус:** закрыт в 0.7.

**Решение.** Пакет — это папка. Обязательных файлов два:

| Файл | Назначение |
|---|---|
| `game.yaml` | манифест: единственное место, где объявлены метаданные игры и сцен |
| `story.md` | все сцены пакета |

Опциональные:

| Файл / папка | Назначение |
|---|---|
| `items.yaml` | предметы (TBD 6) |
| `stats.yaml` | статусы (TBD 7) |
| `flags.yaml` | флаги (TBD 7) |
| `mechanics.yaml` | проверки и бои: `checks`, `combat` ([book-types](book-types/index.md)) |
| `storyGraph.md` | карта ветвлений: выходы сцен, концовки, хабы, Mermaid-граф (§2.3, [story-graph.md](story-graph.md)) |
| `review.md` | сомнительные случаи для человека (§0.5, [review.md](review.md)) |
| `theme.yaml` | тема оформления: TBD 9, в профиль формата пока не входит |
| `assets/` | изображения и звук; пути только относительные от корня пакета |
| `soundtrack.md` | бриф композитору: настроение каждой сцены и главы по настроению; движок не читает |
| `illustrations.md` | бриф художнику: что нарисовать и к каким сценам; движок не читает |

Поля `game.yaml`:

```yaml
format: quest/1        # версия формата, обязателен
id: koshchei-cave      # ASCII-слаг, обязателен
title: Кощеева пещера
type: storybook        # storybook | fighting-fantasy | rpg | hybrid
status: complete       # complete | fragment
author: Гарри Гаррисон # для карточки в библиотеке; нет — прочерк
genre: фантастика · книга-игра   # свободная строка; нет — прочерк
annotation: Краткое описание книги для библиотеки, 1–3 предложения.  # нет — прочерк
illustrator: Иван Иванов  # если указан в книге
translator: —          # если книга переводная
edition: 1995, Москва  # выходные данные
year: 1995
source: koshchei-cave.txt
cover: assets/cover.webp  # обложка для библиотеки
language: ru
start: cave_entry      # id стартовой сцены, обязателен
story: story.md        # по умолчанию story.md
items: items.yaml      # только если файл есть; иначе ключ не пиши
start_items:           # с чем игрок начинает; id из items.yaml
  sword: 1             # карта id: количество; список допустим, если плеер умеет
  sleep_grenades: 2
stats: stats.yaml      # только если файл есть; иначе ключ не пиши
flags: flags.yaml      # только если файл есть; иначе ключ не пиши
mechanics: mechanics.yaml  # опционально: проверки и бои
moods:                 # настроения сцен: ключ → трек, список треков или null
  calm: assets/audio/calm.ogg
  tense: assets/audio/tense.ogg
  mystery: null        # настроение размечено, трека пока нет
theme: theme.yaml      # TBD 9
scenes:                # метаданные сцен, см. TBD 2
  cave_entry:
    title: Вход в пещеру
```

**Настроения.** `null` у настроения значит «размечено, музыки нет»: сцена с таким
настроением продолжает текущий трек. `mood` обязателен у каждой сцены, поэтому
`default_mood` не нужен. Подробно — [soundtrack.md](soundtrack.md).

**Опциональные файлы.** `items`, `stats` и `flags` — не значения по умолчанию.
Если файла нет, ключ не пиши; отсутствие ключа означает отсутствие механики. Плеер
не должен запрашивать `items.yaml`/`stats.yaml`/`flags.yaml` «на всякий случай»:
иначе книга без предметов получает 404. Пустые файлы тоже не нужны.

**Карточка книги.** `title`, `author`, `genre`, `annotation`, `illustrator` и `cover`
предназначены для карточки книги; `genre` — это жанр, а не формат, поэтому не
дублируй в нём «книга-игра» (для этого есть `type`). Необязательные поля при
отсутствии печатаются прочерком. Ничего не выдумывай: поля берутся из книги,
выходных данных или предисловия; правила и приоритет источников —
[metadata.md](metadata.md). Конкретный плеер может показывать не все поля: текущий
MVP выводит `title`, `author`, `genre`, `type`, `annotation` и прогресс, а `cover`,
`illustrator`, `translator`, `status` пока не показывает — см.
[handoff.md](handoff.md).

**Тип и статус.** `type` определяет правила разбора и набор файлов
([book-types/index.md](book-types/index.md)). `status: fragment` ставится только
после решения человека продолжать ознакомительный фрагмент ([source.md](source.md)).
Поле подтверждается человеком, как и тип.

**Правила:**

- кодировка всех файлов — UTF-8; другая кодировка — ошибка валидатора;
- имена файлов и папок — ASCII, без пробелов;
- ссылки на ассеты только относительные и внутри пакета; `..`, абсолютные пути и
  внешние URL — ошибка;
- `format` обязателен: пакет без версии формата не запускается;
- `start_items` — стартовый инвентарь: список id (количество 1) или отображение
  `id: количество`; каждый id обязан быть объявлен в `items.yaml`, иначе ошибка
  (`E_START_ITEM_UNKNOWN`). Поле нужно потому, что книжный герой почти всегда «уже
  вооружён», и без него предметы появляются только эффектами `take`. Формат
  допускает обе записи, но конкретный плеер может понимать только карту — проверяй
  [handoff.md](handoff.md);
- структура пакета одна и та же для любой книги: предзагруженной или собранной заново;

### 2.4. Несколько изображений у сцены

Одно изображение — поле `image`. Если у сцены их несколько:

```yaml
"24":
  title: Глава 24
  image: illustrations/24-1.webp
  images:
    - illustrations/24-2.webp
    - illustrations/24-3.webp
```

- `image` остаётся главным кадром (то, что видно сразу);
- `images` — дополнительные, порядок задаёт галерею;
- дубликаты путей запрещены;
- сцена без `image`, но с `images` не считается ошибкой: главный кадр берётся из
  первого элемента.

### 2.5. Механики: `mechanics.yaml`

Проверки и бои живут отдельным файлом, чтобы манифест не разрастался:

```yaml
checks:
  - scene: "28"
    stat: charisma
    compare: "< 3"
    success: "292"
    failure: "309"
combat:
  - scene: "45"
    enemy: { name: Зомби, count: 19, attack: 1, health: 1 }
    weapon: [knife, shotgun, submachine, grenade]
    win: "149"
    # необязательные особые поля:
    # lose: "310"
    # preDamage: "2d6+1"
    # preDamageFrom: ["200", "253"]
    # preStamina: 6
    # threshold: 20
    # bonusDamage: "1d6+2"
```

- `scene` — сцена начала боя; `enemy.count` нужен для запуска боя;
- `enemy.attack` — урон каждого выжившего; `enemy.health` — здоровье врага;
- `weapon` — список id оружия из `items.yaml`; `[]` оставляет кулаки;
- `win` обязателен; `lose` необязателен, поражение обрабатывается общим экраном
  смерти;
- `preDamage`/`preDamageFrom` — уже случившийся урон (граната, первый залп);
- `preStamina` — фиксированная потеря Выносливости до раунда;
- `threshold` — победа при суммарном уроне не ниже порога;
- `bonusDamage` — дополнительный бросок к урону.

Правила заполнения и статус — [book-types/rpg.md](book-types/rpg.md) и
[book-types/fighting-fantasy.md](book-types/fighting-fantasy.md). Движок MVP ведёт
бои, выбор оружия, лечение, поражение и повтор; неполные записи помечаются в
`review.md`.

**Лавка.** Покупки задаются у сцены, а не вариантами `story.md`:

```yaml
"329":
  title: Параграф 329
  mood: grief
  shop:
    - {item: pulley, price: 1}
    - {item: hacksaw, price: 1}
    - {item: rubber_gloves, price: 1}
  variants: {А: "28", Б: "157"}
```

`item` обязан быть объявлен в `items.yaml`, `price` — неотрицательное число.
Покупка списывает `money` и добавляет предмет в инвентарь; повторная покупка
невозможна, если предмет уже есть.

## 5. TBD 4. Условия

**Статус:** закрыт в 0.8.

**Решение.** Условие — строка с префиксными предикатами. Ключевые слова латиницей в
нижнем регистре, идентификаторы — те же слаги, что везде в формате.

```text
has_item rusty_key
flag door_open
stat hp <= 3
has_item rusty_key and not flag door_open
(stat hp < 5 or flag desperate) and has_item potion
```

**Грамматика:**

```text
expr      := or
or        := and ("or" and)*
and       := unary ("and" unary)*
unary     := "not" unary | "(" expr ")" | predicate
predicate := "has_item" ID | "flag" ID | "stat" ID CMP INTEGER
CMP       := "=" | "==" | "!=" | "<" | "<=" | ">" | ">="
```

**Семантика:**

- `has_item x` — предмет `x` есть в инвентаре: для считаемого это количество больше нуля;
- `flag x` — флаг `x` установлен; неустановленные флаги ложны;
- `stat x <оп> N` — сравнение числового статуса с целым числом;
- приоритет: `not`, затем `and`, затем `or`; скобки меняют порядок;
- `=` и `==` — одно и то же.

**Ошибки валидатора:**

- неизвестный предикат;
- неизвестный идентификатор предмета, флага или статуса;
- нецелое число в сравнении;
- незакрытая скобка или оборванное выражение — с указанием позиции;
- пустое условие (`if:` без значения); если условия нет — ключ `if` не пишется.

**Не поддерживается:** условия на сцене (только на выборах), проверка посещённых сцен
(`visited`), счётчики и вычисляемые значения внутри условий. `visited` отложен.

## 6. TBD 5. Эффекты

**Статус:** закрыт в 0.8.

**Решение.** Эффект — пара `key: value`, где ключ задаёт глагол. Состав закрыт, другие
глаголы не поддерживаются.

| Ключ | Значение | Смысл |
|---|---|---|
| `if` | условие | применять эффект `on_enter` только если условие истинно |
| `take` | id, список id или `{id: количество}` | добавить предмет (по умолчанию 1) |
| `use` | id (bare, без скобок) | применить предмет: уменьшить количество или убрать |
| `drop` | id или список id | выбросить предмет целиком |
| `set` | id или список id | установить флаг |
| `stat` | отображение id → целое | изменить статус на дельту |

`use` принимает ровно один bare id: `use: medkit`, а не `use: [medkit]`. Квадратные
скобки допустимы у `take`, `drop` и `set`; у `use` — только один id. Иначе `[medkit]`
становится id предмета и валидатор выдаёт `E_EFFECT_UNKNOWN_ID` (или отдельный
`E_EFFECT_USE_FORMAT`).

**Порядок применения:**

- модификатор выбора — слева направо, как записан; внутри списка — по порядку элементов;
- при переходе: сначала эффекты выбора, затем `on_enter` целевой сцены;
- `on_enter` срабатывает при **каждом** входе в сцену, включая повторный;
- `on_enter` записывается в `game.yaml` как YAML-последовательность:

```yaml
scenes:
  cave_hall:
    on_enter:
      - set: entered_hall
      - stat: {hp: -1}
      - if: not has_item pistol   # условная выдача
        take: {pistol: 1}
```

**Семантика:**

- у несчитаемого предмета (`countable: false`) `take` уже имеющегося не создаёт дубликат,
  а у считаемого — прибавляет количество;
- `use` уменьшает количество на 1 у расходника и убирает одноразовый предмет; на
  многоразовом предмете `use` запрещён;
- `if` на элементе `on_enter` проверяется тем же `evalCond`, что и условия
  выбора; при ложном условии весь элемент пропускается; это нужно для находок
  вида «если вы ещё не осматривали ящик»;
- `drop` отсутствующего предмета — no-op в рантайме; предупреждение валидатора, если
  предмет не выдаётся ни в одном месте пакета;
- `set` уже установленного флага — no-op; снятие флага не поддерживается
  (вместо этого вводится второй флаг);
- `stat` прибавляет дельту к текущему значению и обрезает результат по диапазону
  статуса (диапазон — TBD 7); дельта `0` — ошибка валидатора;
- эффекты статичны: условных эффектов и вычисляемых выражений нет, ветвление — только
  через выборы и сцены (§1.2, [AGENTS.md](../AGENTS.md)).

**Ошибки валидатора:** неизвестный ключ, неизвестный предмет/флаг/статус, нецелая
дельта, эффект в месте, где он не поддерживается.

**Не поддерживается:** снятие флага (`clear`), одноразовые эффекты (`once`),
эффекты с условием, эффекты при выходе из сцены.

## 10. TBD 9. Тема оформления: отложен

**Статус:** решение отложено (TBD 9). В профиле формата тема пока не фиксируется.

Что уже понятно:

- тема подчиняется (§1.2, [AGENTS.md](../AGENTS.md)): авторы не пишут CSS;
- тема — необязательный `theme.yaml`, только токены из белого списка;
- пока пакет тему **не задаёт**: движок использует одну встроенную базовую тему;
- решение определит набор токенов, проверку контраста и необходимость пресетов.

Вопросы к решению:

- список токенов: цвета, шрифты, ширина колонки, отступы, фон;
- допустимые значения: hex-цвета, встроенные шрифты, без загрузки шрифтовых файлов;
- проверка контраста text/background как предупреждение валидатора;
- частичная тема: незаданные токены берутся из базовой;
- нужны ли готовые пресеты (`light`, `dark`, `parchment`) вместо ручных токенов.

## 11. TBD 10. Валидатор: ошибки и предупреждения

**Статус:** отложен. Политика, формат сообщений и глубина
проверки проходимости сознательно не фиксируются в 0.11.

### 11.1. Что отложить нельзя

Без этих проверок пакет не пригоден к запуску — они обязательны независимо от того,
каким будет полный каталог:

| Код | Почему обязателен |
|---|---|
| `E_PKG_NO_MANIFEST`, `E_PKG_MISSING_STORY` | нечего разбирать |
| `E_PKG_FORMAT_MISSING`, `E_PKG_FORMAT_UNSUPPORTED` | неизвестная версия формата |
| `E_PKG_PATH_ABSOLUTE` | выход за пределы пакета |
| `E_SCENE_NO_META`, `E_SCENE_META_ORPHAN` | иначе неясно, где чьи метаданные |
| `E_SCENE_DUPLICATE`, `E_SCENE_ID_INVALID` | иначе переход неоднозначен |
| `E_SCENE_START_MISSING` | игру невозможно начать |
| `E_SCENE_DEAD_END`, `E_SCENE_EXIT_CONFLICT` | тупик или два выхода сразу |
| `E_TARGET_MISSING` | переход в пустоту |
| `E_MODIFIER_UNKNOWN_KEY`, `E_EFFECT_UNKNOWN_KEY` | движок не знает, что исполнять |
| `E_COND_UNKNOWN_ID`, `E_EFFECT_UNKNOWN_ID` | опечатка ломает логику молча |
| `E_EFFECT_USE_FORMAT` | `use` записан списком/в скобках и не будет найден |
| `E_ASSET_MISSING` | картинка или музыка не загрузится |
| `E_MOOD_UNKNOWN`, `E_MOOD_MISSING` | настроение не объявлено или не задано |
| `E_DICE_NO_FALLBACK` | бросок без запасного исхода |
| `E_TAG_UNBALANCED`, `E_TAG_REF_MISSING` | тег и отсылка разъехались |
| `E_VARIANT_LETTER_MISSING`, `E_VARIANT_KEY_MISSING` | буква и цель варианта разъехались |

### 11.2. Черновой каталог [предложение]

Полный каталог для обсуждения. Уровень: `E` — ошибка, `W` — предупреждение.

| Код | Ур. | Что проверяет |
|---|---|---|
| `E_PKG_NO_MANIFEST` | E | нет `game.yaml` |
| `E_PKG_FORMAT_MISSING` | E | нет поля `format` |
| `E_PKG_FORMAT_UNSUPPORTED` | E | версия формата не поддерживается |
| `E_PKG_ENCODING` | E | файл не в UTF-8 |
| `E_PKG_FILE_NAME` | E | имя файла не ASCII |
| `E_PKG_PATH_ABSOLUTE` | E | абсолютный путь, `..` или внешний URL |
| `E_PKG_MISSING_STORY` | E | нет файла из `story:` |
| `W_PKG_UNKNOWN_FIELD` | W | неизвестное поле манифеста |
| `W_PKG_ID_FOLDER_MISMATCH` | W | `id` не совпадает с именем папки пакета: плеер может использовать имя папки для API и сейвов |
| `E_SCENE_ID_INVALID` | E | id не номер главы и не слаг (`^([a-z][a-z0-9_]*|[0-9]+)$`) |
| `E_SCENE_DUPLICATE` | E | повторяющийся id |
| `E_SCENE_NO_META` | E | заголовок `##` без записи в `scenes` |
| `E_SCENE_META_ORPHAN` | E | запись в `scenes` без заголовка |
| `E_SCENE_START_MISSING` | E | `start` указывает на несуществующую сцену |
| `E_SCENE_DEAD_END` | E | нет `variants`/`next` и нет `ending: true` |
| `E_SCENE_EXIT_CONFLICT` | E | одновременно `next`, `variants` или `ending` |
| `E_SCENE_NO_TITLE` | E | нет `title` |
| `E_SCENE_H1` | W | заголовок `#` в `story.md` |
| `W_SCENE_UNREACHABLE` | W | сцена недостижима из `start` |
| `W_SCENE_EMPTY` | W | нет текста, выборов и эффектов |
| `W_ENDING_UNREACHABLE` | W | есть недостижимая концовка |
| `E_TARGET_MISSING` | E | цель `next`, `variants` или `goto` не существует |
| `E_VARIANT_LETTER_MISSING` | E | тег/отсылка `[А]` без ключа в `variants` |
| `E_VARIANT_KEY_MISSING` | E | ключ `variants` без тега/отсылки |
| `E_TAG_UNBALANCED` | E | `{А}` без `{/А}` или наоборот |
| `E_TAG_REF_MISSING` | E | тег без `[А]` внутри или отсылка без тега |
| `E_MODIFIER_UNKNOWN_KEY` | E | неизвестный ключ модификатора варианта |
| `E_KEY_FORMAT` | E | ключ не номер главы и не слаг |
| `E_KEY_UNQUOTED` | E | числовой ключ в манифесте без кавычек |
| `W_NAV_IN_PROSE` | W | в прозе остался номер отсылки (не адресная формула) |
| `W_VARIANT_DUPLICATE_TARGET` | W | два варианта ведут в одну сцену |
| `E_DICE_SYNTAX` | E | неверная запись броска |
| `E_DICE_NO_FALLBACK` | E | в `next.outcomes` нет исхода без `min` |

**Недостижимые сцены — предупреждение, а не ошибка.** Страховочный финал («если
предметов не хватило») может быть недостижим по графу и при этом полезен как защита от
будущих правок. В книгах встречаются и страницы-сироты: сцены, на которые не ведёт ни
одна ссылка. И то и другое допустимо, если человек подтвердил случай в `review.md`;
удалять или пришивать такие сцены автоматически нельзя.

### 11.3. Открытые вопросы

1. **Политика предупреждений:** запуск разрешён или предупреждения тоже блокируют?
   Варианты: разрешён и показываются; блокируют; показываются только автору.
2. **Формат сообщения:** стабильный код + человеческий текст; только текст; код без текста.
3. **Глубина проверки проходимости:** только висячие ссылки; граф достижимости сцен и
   концовок; полный перебор с учётом условий (решатель).
4. **Где показывать:** экран ошибки перед запуском игры или отдельный «отчёт валидатора».
5. **Язык сообщений:** русский; английский — после локализации.

### А.5. Что проверяет пример

- пять сцен в одном файле, id берутся из заголовков `##`;
- метаданные сцен — только в `game.yaml`, расхождение с заголовками ловит валидатор;
- две концовки помечены `ending: true`, тупиков нет;
- `cave_walls` возвращает назад — цикл не считается ошибкой;
- выбор «Открыть сундук» скрыт, пока нет ключа, и исчезает после первого открытия (флаг);
- предмет выдаётся эффектом на выборе, а не отдельной сценой-прокладкой;
- `stat` на входе в зал показывает дельту и обрезку по `min`;
- картинка и музыка заданы только у части сцен — они опциональны;
- все предметы, статусы и флаги объявлены в своих файлах, поэтому опечатка в любом
  идентификаторе — ошибка, а не тихо созданная сущность.
