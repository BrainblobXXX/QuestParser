# Отчёт о сомнительных случаях: `review.md`

> Часть инструкции QuestRules. Точка входа — [AGENTS.md](../AGENTS.md).
>
> Коды `C_*`, приоритеты, статусы и порядок разбора отчёта.

### 0.5. Сомнительные случаи: `review.md`

Конвертация не останавливается на непонятном месте. Каждое сомнение попадает в
`review.md` в папке пакета, конвертер принимает безопасное решение по умолчанию и идёт
дальше. Файл читает человек, движок его игнорирует.

**Зачем:** отделить механическую работу от решений, которые нельзя принять без
человека. Если случай попал в файл — он редкий и требует внимания; всё остальное
разобрано автоматически. Это и есть фильтр: сто спорных мест в книге превращаются в
список из десяти строк, а не в сто молча принятых решений.

**Формат:** таблица, по строке на случай.

| № | Сцена | Код | Приоритет | Фрагмент | Что сделано | Что проверить | Статус |
|---|---|---|---|---|---|---|---|
| R-001 | 232 | `C_NAV_AMBIGUOUS` | спорно | «Если уходишь, то на [А]; если остаёшься — на [Б].» | клаузы обёрнуты тегами, `[А]` и `[Б]` внутри | не потерялся ли смысл | open |

**Коды** (префикс `C_` — converter, это не коды валидатора):

| Код | Когда ставится |
|---|---|
| `C_STRUCTURE_GUESSED` | структура секций восстановлена по смыслу, а не найдена в разметке |
| `C_REF_UNRESOLVED` | отсылка ведёт на несуществующую секцию или у варианта вовсе нет адреса (буллет без номера): цель не выдумывается |
| `C_REF_AMBIGUOUS` | число похоже на отсылку, но может быть частью текста (год, сумма) |
| `C_NAV_AMBIGUOUS` | неясно, какую фразу помечать тегом варианта |
| `C_DICE_OR_CHOICE` | неясно, случайность это или решение игрока |
| `C_LABEL_EMPTY` | устарел в 0.49: подпись — буква, пустой быть не может |
| `C_LABEL_LONG` | устарел в 0.49: подпись не обрезается |
| `C_CHAPTER_TITLE` | у главы нет названия, взято «Глава N» |
| `C_MECHANICS` | в книге есть механика (очки, предметы), не перенесённая в пакет |
| `C_MECHANICS_ADDED` | в пакет добавлена механика, которой нет в книге (например, условия на деньги): это авторская правка |
| `C_ACHIEVEMENT_FLAG` | достижение книги («получено достижение «…»», «Если отмечено «…»») смоделировано флагом; бейдж убран как служебный — проверить выдачу и проверку |
| `C_FLAG_ENGINE_UNSUPPORTED` | сюжет держится на флагах, а целевой плеер не применяет `set`/`if: flag`: условные варианты мертвы; выбор — флаги, stats 0/1 или блокер |
| `C_DYNAMIC_LINK` | динамический переход («к параграфу с тем же номером»), который формат не выражает |
| `C_CODE_DYNAMIC` | переход задан кодом «параграф ± число»; вынесен в `codes.yaml` + `learn_code`, число осталось в прозе как подпись кода |
| `C_CODE_RESOLVED` | код с явной базой («к параграфу магазина – 197») разрешён в `base`+`offset`; проверить, что база — та сцена |
| `C_CODE_ENGINE_UNSUPPORTED` | книга держится на кодах, а целевой плеер не знает `codes.yaml`/`learn_code`. MVP 0.65 поддерживает; код остаётся для другого плеера |
| `C_CODE_UNRESOLVED` | ни из одной сцены смещение не даёт существующую сцену: код объявлен, но бесполезен; возможно, не найдена база |
| `E_SCENE_MISSING` | (Quest/2 validator) цель перехода/условия не существует |
| `E_ITEM_MISSING` | (Quest/2 validator) предмет не объявлен |
| `E_STAT_MISSING` | (Quest/2 validator) статус не объявлен |
| `E_FLAG_MISSING` | (Quest/2 validator) флаг не объявлен |
| `E_CODE_MISSING` | (Quest/2 validator) код не объявлен |
| `E_CODE_TARGET` | (Quest/2 validator) цель кода с явной базой не существует |
| `E_ROLL_GAP` / `E_ROLL_OVERLAP` | (Quest/2 validator) диапазоны броска не покрывают значения или пересекаются |
| `E_DEAD_END` | (Quest/2 validator) не-концовка не имеет выхода |
| `E_ENDING_INTERACTION` | (Quest/2 validator) у концовки есть `interaction` |
| `W_UNREACHABLE` / `W_UNREACHABLE_ENDING` | (Quest/2 validator) недостижимая сцена/концовка |
| `C_ITEMS_EXTRA` | в пакет добавлены предметы для антуража, хотя книга не проверяет их условиями |
| `C_ITEMS_UNTRACKED` | предметы упомянуты в прозе и вариантах, но проверок на них нет |
| `C_ITEM_NO_SOURCE` | предмет проверяется условием, но книга нигде его не выдаёт: условие не ставится, ветка остаётся доступной |
| `C_ITEM_LOST` | в тексте предмет найден/взят, но `take` отсутствует: ошибка конвертера, а не книги; проверить цитату и выдачу |
| `C_ITEM_SHOP` | предмет продаётся в лавке, но `shop` у сцены не описан; в MVP 0.65 добавлены `shopTitle`/`shopCurrency`, но не все магазины книги размечены |
| `C_ITEM_CHOICE_UNSUPPORTED` | выбор игрока внутри эффекта («вычеркните лучшее оружие») не выражается обычным `drop`; в MVP 0.65 для «лучшего оружия» есть `dropBestWeapon` |
| `C_EFFECT_REPEAT` | старая проблема повторной выдачи `on_enter.take`; в MVP 0.65 предметы выдаются только при первом входе, код остаётся для истории |
| `C_CONTENT_ADDED` | добавлены сцены, варианты, концовки или названия глав, которых нет в книге |
| `C_LABEL_ODD` | устарел в 0.49: подпись не зависит от текста |
| `C_REF_WORDED` | отсылка записана словами («к тридцатой главе»), а не номером |
| `C_LABEL_CONTEXT` | устарел в 0.49: контекст остаётся в тексте рядом с тегом |
| `C_TAGS_BROKEN` | отсылки в книге расставлены с ошибкой: тег стоит посреди чужой фразы |
| `C_MARKDOWN_UNRENDERED` | в прозе осталась Markdown-разметка (`###`, `**`, списки), которую целевой плеер показывает как обычный текст; нужно перевести в plain text или включить рендер |
| `C_CONDITION_PROSE` | в прозе спрятано условие входа («после двух побед»), нужен `if` и статус |
| `C_ILLUSTRATION_JUMP` | сцена меняет кадр без глагола движения — проверить разметку |
| `C_ILLUSTRATION_UNKNOWN` | у сцены нет ни перехода, ни лексики места, ни родителей |
| `C_ILLUSTRATION_NO_EVIDENCE` | кадр поставлен без цитаты-доказательства, или цитата не найдена в тексте сцены |
| `C_ILLUSTRATION_AMBIGUOUS` | в сцене два разных кадра, или родители наследуют разные кадры |
| `C_ILLUSTRATION_TOPO_UNKNOWN` | названное место не отображено в кадр: топоним, деревня, перекрёсток |
| `C_ASSET_MISMATCH` | файл иллюстрации не соответствует описанию в брифе |
| `C_ASSET_UNUSED` | файл в пакете не привязан ни к одному кадру и не помечен как неиспользуемый |
| `C_MOOD_NO_EVIDENCE` | настроение сцены не подтверждено сильной цитатой из неё |
| `C_MOOD_MISMATCH` | бриф `soundtrack.md` и `scenes.*.mood` в манифесте расходятся |
| `C_MOOD_TRACK_MISSING` | настроение объявлено как `null`: трека ещё нет, сцена продолжит текущий |
| `C_FRAME_MISSING` | у сцены нет кадра, хотя в каталоге есть подходящий файл |
| `C_TEXT_FRAGMENT` | после разметки фраза читается плохо |
| `C_SCENE_DEAD_END` | листовая сцена объявлена концовкой (`ending: true`), но финальной фразы (в том числе по смыслу) в тексте нет: возможно, это обрыв, а не финал |
| `C_SOURCE_FRAGMENT` | текст похож на ознакомительный фрагмент: ссылки ведут за последнюю секцию или найден маркер магазина |
| `C_SOURCE_PROTECTED` | PDF запрещает копирование (`copy:no`), `pdftohtml` не открывает файл; текст извлечён `pdftotext`/`-bbox`, цели проверены по графу |
| `C_STATUS_FRAGMENT_MISMATCH` | статус `fragment` не сходится с маркером: маркер есть, статуса нет — или наоборот |
| `C_FRAGMENT_GAP` | при `status: fragment` ссылка ведёт за границу найденных секций |
| `C_SECTION_AMBIGUOUS` | неясно, номер это страницы или секции |
| `C_SECTION_GAP` | в нумерации секций пропуск |
| `C_HEADER_NOISE` | в тексте остались колонтитулы, номера страниц или мусор магазина |
| `C_REF_MIXED` | сцена использует не доминирующий стиль отсылок |
| `C_INLINE_CHOICE` | неясно, как нарезать абзац с отсылками на клаузы |
| `C_TEXT_DUPLICATE` | абзацы дублируются, сходство неполное или спорное |
| `C_TEXT_DUPLICATE_FULL` | несколько секций полностью совпадают: сцены не сливаются, группа уходит в отчёт одной строкой |
| `C_TYPE_AMBIGUOUS` | тип книги не определён: нужен выбор человека |
| `C_TYPE_HYBRID` | смешанный тип: спорный момент расходится с правилами выбранного типа |
| `C_CHECK_INCOMPLETE` | у проверки нет одного из исходов |
| `C_CHECK_UNSUPPORTED` | проверка не выражается текущим форматом; в MVP 0.65 поддержаны `2d6 + stat`, выражения и Fallout-проверки навыков |
| `C_CHECK_PROSE` | проверка спрятана в прозе, цели у неё нет: условие не ставится, случай в отчёт |
| `C_COMBAT_INCOMPLETE` | у боя нет `count`, `win` или не заполнены особые поля (`preDamage`, `threshold`, `preStamina`) |
| `C_COMBAT_UNSUPPORTED` | бой найден, но не описан в `mechanics.yaml`; для контестного/ролевого боя — только если целевой плеер не читает `defense`/`enemies` |
| `C_COMPANION_UNSUPPORTED` | у боя есть спутник/союзник со своим здоровьем, выбором цели или «если она погибла»: схема `combat` этого не выражает, ветка остаётся недостижимой — подтвердить у человека |
| `C_CALL_RETURN_UNSUPPORTED` | сцена-подпрограмма с возвратом «к тому параграфу, откуда пришёл»: формат не умеет call/return; вызовы встраиваются в вызывающие сцены, страница остаётся helper'ом |
| `C_GAMBLE_UNSUPPORTED` | ставка, переменная сумма, выплата «ставка + столько же» или полосы исхода не выражаются `stat`/`next.roll`/`checks`; в MVP 0.65 поддержаны `gambles` ([manifest.md](manifest.md) §2.6) |
| `C_STAT_AMBIGUOUS` | неясно, к какому стату относится изменение |
| `C_STAT_START_UNSOURCED` | стартовое значение статуса не названо в тексте сцены: взято из названия, аннотации или правил |
| `C_ITEM_AMBIGUOUS` | предмет упомянут, но механика не ясна |
| `C_META_MISSING` | нет `title`, `language`, `status` или `type` |
| `C_META_DOUBT` | данные расходятся между титулом, обложкой и выходными данными |
| `C_COVER_DOUBT` | файл обложки не найден или не открывается |
| `C_IMAGE_UNMAPPED` | иллюстрация из книги не привязана к сцене |
| `C_IMAGE_DUPLICATE` | одинаковые изображения извлечены несколько раз |
| `C_IMAGE_REUSED` | один файл стоит у нескольких сцен: при одинаковом тексте или одинаковом действии — общий кадр (`ok`), иначе проверить, не украшение |
| `C_IMAGE_ORNAMENT` | изображение похоже на украшение или логотип, а не на кадр |
| `C_ASSET_RIGHTS_WARN` | иллюстрации из книги: предупреждение о правах и ответственности |

**Приоритет:** `блокер` — игра не запустится; `спорно` — запустится, но может быть
неверно; `мелко` — оформление, не влияющее на смысл (например, выбор цитаты в брифе).

**Статус:** `open` — ждёт человека; `ok` — проверено и принято; `fixed` — исправлено;
`wontfix` — человек явно отказался менять, решение принято как есть.

**Потерянные выдачи — отдельный класс ошибок.** Если проза говорит «находите»,
«берете», «кладете в сумку», а `take` отсутствует, это `C_ITEM_LOST`; аудит
обязан пройти по глаголам получения, а не только по условиям `has_item`.
Единица `ammo` — коробка; количество сверяется с текстом. Лавка описывается
`shop` у сцены; иначе — `C_ITEM_SHOP`.

**Предметы без проверок — всегда спорный случай.** Если предметы фигурируют в прозе и в
вариантах, а книга нигде не проверяет их наличие, конвертер не решает сам, тратить ли
предмет и ставить ли условие: он выбирает безопасное поведение (не тратит, не
блокирует), а случай заносит в `review.md` с кодом `C_ITEMS_UNTRACKED` и приоритетом
`спорно`. Тратить предмет, добавлять `if: has_item` или заводить количество — решение
человека, а не автоматики.

**Аудит предметов — обязательный раздел отчёта.** Когда предметы всё-таки
смоделированы (выдачи `take`, условия `if`, траты `use`/`stat`), в `review.md`
добавляется таблица «Аудит предметов»: предмет → где получен (сцена, количество) →
где проверяется (сцена и вариант) → где тратится (эффект) → статус
(«смоделировано», «выдаётся, но не проверяется», «источник не найден», «только
покупка в лавке», «только в правилах»). Под таблицей — цитаты-доказательства
выдач. Это единственный способ проверить модель на книге в 50+ предметных
проверок: глазами такой объём не сходится. Образец — пакет ZombieBlood
([case-zombieblood.md](case-zombieblood.md)).

**Если предметы есть, а механики нет**, `items.yaml` не заводится, но таблица
аудита всё равно заполняется со статусом «только в прозе»: так видно, что
предметы не потеряны, а сознательно не смоделированы. Образец —
[case-kupalo.md](case-kupalo.md).

**Аудит денег — тот же обязательный раздел, если книга считает деньги.** Таблица
«сцена → где (вход в сцену или вариант) → цитата → дельта» плюс проверка модели: сколько
трат на простых путях (без повторного входа в сцену), укладываются ли они в `initial`,
сходятся ли провальные концовки с текстом («осталось ничего» — это ровно 0, «голодал» —
200–400). Правило размещения эффекта — [stats.md](stats.md)
§8.1.1; образец — пакет «Как прожить месяц на 2500 рублей» ([case-2500.md](case-2500.md)).

**Словесные отсылки — всегда спорный случай.** Бывает, что номер главы записан словом, а
не цифрой: «НЕМЕДЛЕННО ОТПРАВЛЯЙСЯ К ТРИДЦАТОЙ ГЛАВЕ!», в том числе в квадратных скобках.
Такую фразу нельзя молча превратить в переход: номер надо перевести в число, фразу —
заменить на букву и пометить тегом, а случай занести в `review.md` с кодом
`C_REF_WORDED` и подтвердить у человека. Если номер читается неоднозначно («к последней главе»), переход не создаётся, а
сцена помечается блокером.

**Доступность предмета и запасной выход.** Если вариант требует предмета, он
блокируется условием `if: has_item x`. Если после блокировки у сцены не остаётся ни
одного выхода, конвертер обязан добавить запасной вариант и концовку для него — иначе
получится тупик. Такие добавления (сцены, варианты, концовки, которых нет в книге) идут
в `review.md` с кодом `C_CONTENT_ADDED` и требуют подтверждения человеком: это уже
авторская правка, а не перенос текста. Это единственное исключение из правила «не
добавлять сцены, которых нет в книге».

**Подпрограммы и возврат «к вызвавшей сцене».** Книга может отправлять в служебную
страницу: «перейди на 65 и прочитай инструкции, затем вернись сюда», «выполни
инструкции на 33, затем перейди на тот параграф, с которого попал сюда». Формат не
умеет call/return: у сцены один выход, и он не зависит от того, кто её вызвал.
Безопасное решение: исходы такой страницы **встроить в вызывающие сцены** (у каждой
свой `success`/`failure`), а саму страницу оставить helper'ом и честно записать её
недостижимость. Заводить флаг-заглушку нельзя: если страницу никто не вызывает, флаг
неоткуда взять. Код — `C_CALL_RETURN_UNSUPPORTED`; удалённые вызовы — `C_DYNAMIC_LINK`.

**Спутник и вторая сторона боя.** Перед разметкой боя проверь, нет ли в прозе второго
участника: «Девушка: Здоровье 3», «на каждом ходу выбери, кого атакуют», «если она
погибла, перейди на 21». Схема `combat` знает только `win`/`lose` одного врага, поэтому
такая ветка не выражается. Решение: записать основной путь, а недостижимые сцены
оставить в пакете и подтвердить у человека; код — `C_COMPANION_UNSUPPORTED` плюс
`W_SCENE_UNREACHABLE`. Заводить статус здоровья спутника без механики, которая его
меняет, бессмысленно.

**Правила:**

- по умолчанию выбирается безопасное решение: сомнение трактуется как выбор, а не
  кубик; текст сохраняется, а не выбрасывается; механика не выдумывается;
- если правило допускает несколько вариантов, это не ошибка: конвертер выбирает
  безопасный, перечисляет альтернативы в `review.md`, решение — за человеком;
- чисто адресные фразы («Тогда ты — на 232») и навигационные строки-действия
  («продолжить — (N)») удаляются штатно по шагу 3 конвертации — это не спорный случай;
  в отчёт попадает только ситуация, когда непонятно, есть ли во фразе смысл кроме
  адреса (`C_NAV_AMBIGUOUS`);
- если безопасного решения нет (битая отсылка) — сцена всё равно собирается, но
  помечается `блокер`;
- иллюстрация без цитаты-доказательства не ставится никогда: сцена остаётся без
  `image`, даже если кадр кажется очевидным (этап 5 в [illustrations.md](illustrations.md));
- разбор отчёта — часть работы ИИ, а не задача человека: после сборки ИИ сам задаёт
  вопросы по открытым пунктам (А.8, conversion.md, шаг 12);
- `review.md` не участвует в валидации движка и не влияет на запуск игры;
- приёмка: пакет готов, когда в `review.md` нет `open`; `wontfix` — допустимое решение,
  а не долг;
- если один код повторяется больше десяти раз — это системный случай: одна строка с
  количеством и тремя примерами, а не тридцать одинаковых. Системная строка почти всегда
  означает, что правило в (А.8, [conversion.md](conversion.md)) описано недостаточно точно;
- файла может не быть, если сомнений не возникло; пустой файл — тоже валидный результат;
- `review.md` пишется на русском: его читает человек, а не движок.

**Фрагмент, тип и картинки — всегда решение человека.** Если найден признак
ознакомительного фрагмента, разбор останавливается и задаётся вопрос: продолжать
или нет (`source.md`). Тип книги подтверждается человеком, а `hybrid` даёт отдельную
строку на каждый спорный момент. Извлечённые из книги иллюстрации сопровождаются
предупреждением о правах: парсер предупреждает, но работу выполняет.
