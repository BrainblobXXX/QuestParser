# Fighting Fantasy: характеристики, бои, расходники

> Часть инструкции QuestRules. Точка входа — [AGENTS.md](../../AGENTS.md).
>
> Правила разбора книг типа `fighting-fantasy`: лист персонажа, стартовые броски,
> бои раундами, еда, аптечки, деньги.

## 1. Признаки

- «лист персонажа» и графы для значений;
- характеристики с бронёй кубиков: «бросьте два кубика и добавьте 20»;
- бои раундами: урон оружием, атака врага, счётчики выживших;
- расходники: еда, аптечки, боеприпасы, зелья;
- деньги и покупки;
- ссылки внутри абзацев и в конце параграфов.

## 2. Лист персонажа

Что распознаётся и куда попадает:

| Элемент книги | Поле пакета |
|---|---|
| Выносливость (Stamina) | `stats.yaml`: `stamina`, диапазон `0…max` |
| Урон (Damage) / сила удара | `stats.yaml`: `damage` |
| Мастерство (Skill) | `stats.yaml`: `skill` |
| Удача (Luck) | `stats.yaml`: `luck` |
| Деньги | `stats.yaml`: `money`, диапазон `0…N` |
| Еда, аптечки | `items.yaml`: расходники с количеством |
| Оружие с уроном | `items.yaml`: `damage: "1d6+5"` |

Стартовые значения не выдумываются: если книга говорит «2d6+20», в сцене старта
остаётся бросок (`roll`), а игрок вводит результат; если значение фиксированное —
пишется число.

## 3. Бои

Бой — не выбор и не `next.roll`. Это отдельная механика в `mechanics.yaml`:

```yaml
combat:
  - scene: "45"
    enemy:
      name: Зомби
      count: 19
      attack: 1          # сколько Выносливости снимает каждый выживший
      health: 1          # здоровье одного врага
    weapon: [knife, shotgun, submachine, grenade]  # id оружия из items.yaml
    win: "149"           # куда идти после победы
    # lose необязателен: если его нет, поражение показывает общий экран смерти
    # lose: "310"
```

Правила заполнения:

- `scene` — сцена, где начинается бой;
- `enemy.count` — число врагов. Для запуска боя в MVP поле должно быть заполнено;
  если число в прозе не названо, это `C_COMBAT_INCOMPLETE`, а не выдуманное число;
- `enemy.attack` — урон каждого выжившего за раунд; `enemy.health` — здоровье
  одного врага. Значения по умолчанию берутся из правил книги;
- `weapon` — **список id оружия** из `items.yaml`, а не строка урона. Урон лежит
  в `items.yaml → damage`. `automatic` — алиас `submachine`; пустой список
  `[]` оставляет только кулаки;
- `win` обязателен: это сцена после победы. `lose` необязателен: если книга не
  даёт отдельную сцену смерти, движок показывает общий экран поражения с повтором;
- бой не должен одновременно иметь `variants`/`next`: переход задаёт `win`.

### 3.1. Особые бои

Схема поддерживает поля, которые понадобились на ZombieBlood:

| Поле | Смысл |
|---|---|
| `preDamage: "2d6+1"` | урон, который уже случился до первого раунда (граната, первый залп) |
| `preDamageFrom: ["200", "253"]` | применять `preDamage` только если бой начат после одной из этих сцен |
| `preStamina: 6` | фиксированная потеря Выносливости до боя |
| `threshold: 20` | победа только если суммарный урон за раунд не меньше порога |
| `bonusDamage: "1d6+2"` | дополнительный бросок к урону (например, пистолет Эми у Зомби Конга) |

`preDamage` — это **модель уже описанного в прозе действия**, а не второй бой.
Если точный остаток врагов зависит от предыдущей сцены, честнее перенести
состояние между сценами; текущий MVP разыгрывает бросок в начале боя и
фиксирует это в `review.md` (`C_STAT_AMBIGUOUS`).

### 3.2. Как вытащить параметры боя из прозы

Признак боя — фраза «Если выиграете/победите - [N]»: это `win`, а сама сцена
получает `next: "<N>"`. Число врагов в тексте называют по-разному:

| Как в книге | Значение `count` |
|---|---|
| «стая из девятнадцати зомби» | 19 |
| «двадцать четыре обезумевших зомби» | 24 |
| «шестерых жутких зомби» | 6 |
| «всего их девятнадцать» | 19 |
| «пятнадцать остались в живых» | 15 |
| «17 собак», «стая огромных серых крыс… всего их пятнадцать» | 17 / 15 |

Правила:

- числительное может стоять за 1–4 слова до существительного и в косвенном
  падеже («девятнадцатью зомби») — нужен разбор словоформ, а не поиск цифры;
- **`attack` и `health` по умолчанию — из правил книги** («каждый зомби имеет 1
  очко Выносливости», «каждый выживший снимает 1 очко»). Если сцена говорит
  иначе, берётся число сцены;
- **`lose` в книге часто не указан**: при нуле Выносливости приключение просто
  заканчивается. Поле не выдумывается; движок использует общий экран смерти;
- **особые бои** не сводятся к обычному `count`/`attack`: для порога используется
  `threshold`, для бонусного оружия — `bonusDamage`, для предбоевого урона —
  `preDamage`/`preStamina`;
- **бой — не выбор.** «Если хотите сразиться с ними - 107» — это выбор, а
  «Вы должны сражаться. Если выиграете - 235» — бой; первое остаётся вариантом.

Проверка: у каждого `combat` есть `count` и `win`, сцена и цель существуют, а
сцена не имеет одновременно `combat` и `variants`.

### 3.3. Что делает движок

MVP ведёт полный бой:

- оружие берётся из инвентаря, урон — из `items.yaml → damage`;
- огнестрельное требует `ammo`, без оружия доступны кулаки `1d6−3`;
- граната применяется до первого раунда, аптечка — между раундами;
- после атаки выжившие враги снимают Выносливость;
- победа сохраняет Выносливость/инвентарь и ведёт в `win`;
- поражение показывает «ВЫ ПОГИБЛИ», повтор из состояния перед входом в сцену
  или выход в библиотеку;
- бой выводится как продолжение текста главы: раунды и броски дописываются
  абзацами, действия оформлены как варианты перехода; бросок кубика показывается
  явно и анимированно.

## 4. Ресурсы

| Ресурс | Как описан |
|---|---|
| Еда | `items.yaml`: `food`, расходник, `use` восстанавливает `stamina` |
| Аптечка | `items.yaml`: `medkit`, одноразовый, лечит до стартового максимума |
| Боеприпасы | `items.yaml`: `ammo`, единица = коробка; по правилам после находки расход не считается |
| Деньги | `stats.yaml`: `money`; лавка — `scenes.*.shop` |

«Потеряйте 3 очка Выносливости» → эффект `stat: stamina -3` на сцене.
«Восстановите Выносливость» без числа → `review.md`, пока не ясно, до какого уровня.

## 5. Формат пакета

| Файл | Нужен |
|---|---|
| `story.md` | да |
| `game.yaml` | да, `type: fighting-fantasy` |
| `stats.yaml` | да |
| `items.yaml` | да, если есть расходники и оружие |
| `mechanics.yaml` | да, если есть бои |
| `flags.yaml` | редко |

## 6. Что уже умеет формат и что расширим

| Возможность | Статус |
|---|---|
| числовые статы и изменения | есть |
| предметы, расходники, `use` | есть |
| одиночный бросок (`next.roll`) | есть |
| стартовый бросок характеристики | есть как текст + `roll` |
| бой раундами | есть: `mechanics.yaml → combat` |
| выбор оружия в бою | есть: оружие из инвентаря |
| лечение до максимума | есть (эффект `restore`) |
| покупки в лавке | есть: `scenes.*.shop` |
| анимированный бросок | есть в интерфейсе MVP |

## 7. Порядок разбора

1. найти лист персонажа и стартовые значения;
2. выписать характеристики в `stats.yaml` с диапазонами;
3. найти блоки боёв и записать в `mechanics.yaml`: `count`, `attack`, `health`,
   `weapon`, `win`, при необходимости `preDamage`/`preStamina`/`threshold`;
4. найти расходники, оружие и лавку — в `items.yaml` и `scenes.*.shop`;
5. сцены с потерями/лечением — эффекты `stat`;
6. сцены без ссылок — пометить `ending: true`, проверить фразы гибели (нет фразы —
   `C_SCENE_DEAD_END`);
7. прогнать проверки шага 10 и `review.md`.

## 8. Проверки

- `C_COMBAT_UNSUPPORTED` — бой найден, но не описан в `mechanics.yaml`;
- `C_CHECK_UNSUPPORTED` — проверка навыка/характеристики, которую формат не выражает;
- `C_STAT_AMBIGUOUS` — неясно, к какому стату относится изменение;
- `C_ITEM_AMBIGUOUS` — предмет упомянут, но механика не ясна.

## 9. Пример из набора

**ZombieBlood** (Ян Ливингстон): Выносливость = 2d6+20, урон оружием от 1d6 до
2d6+5, еда и аптечки, деньги, 400 параграфов, 39 боевых сцен (все `count` заполнены),
35 книжных иллюстраций (170 объектов PDF). Стартовые правила и бой описаны в
предисловии; после аудита у всех 39 боёв есть `win`, у восьми — особые поля
`preDamage`/`preStamina`/`threshold`.
