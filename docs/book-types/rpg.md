# RPG: навыки, проверки, опыт, торговля

> Часть инструкции QuestRules. Точка входа — [AGENTS.md](../../AGENTS.md).
>
> Правила разбора книг типа `rpg`: характеристики, навыки, проверки, бои, деньги,
> опыт, торговля.

## 1. Признаки

- характеристики персонажа с числами (сила, ловкость, обаяние, интеллект, удача);
- навыки с уровнями (взлом-II, разговор-III, следопыт-II);
- проверки: «проверка по взлому-II», «если ваше обаяние меньше трёх»;
- бои с блоками `АТАКА`, `ЗАЩИТА`, `ЖИЗНИ`, оружием и уроном;
- деньги, цены, торговля;
- опыт, перки, награды;
- инвентарь с оружием и снаряжением;
- часто — большие книги (сотни параграфов) и развёрнутые правила в предисловии.

## 2. Характеристики и навыки

| Элемент книги | Поле пакета |
|---|---|
| сила, ловкость, обаяние, интеллект, удача | `stats.yaml`, диапазон `1…10` (по книге) |
| здоровье / жизни | `stats.yaml`: `health` |
| деньги | `stats.yaml`: `money` |
| опыт | `stats.yaml`: `experience` |
| навык «взлом-II» | `stats.yaml`: `lockpick`, значение `2` |
| перк | `flags.yaml`: флаг `perk_<имя>` |

Значения и диапазоны берутся из книги; если диапазон не указан — `review.md`,
а не догадка.

## 3. Проверки

Проверка — это не выбор. Она записывается в `mechanics.yaml`:

```yaml
checks:
  - scene: "28"
    stat: charisma
    compare: "< 3"
    success: "292"
    failure: "309"
  - scene: "4"
    stat: lockpick          # навык — такой же статус в stats.yaml
    compare: ">= 2"
    success: "310"
    failure: "315"
```

Правила:

- `success`/`failure` обязательны; нет одного из исходов — `C_CHECK_INCOMPLETE`;
- проверка, замаскированная под выбор («если ваше обаяние меньше трёх – 309, иначе –
  292»), распознаётся по числовому сравнению и уходит в `checks`, а не в варианты;
- проверка без числа («проверьте удачу») — `C_CHECK_PROSE`/`C_CHECK_UNSUPPORTED`;
- **проверка способности — не повод ставить `rpg`.** «Брось `2d6` и прибавь Удачу,
  сравни с Оркишностью + 5» без навыков, опыта и торговли — это `fighting-fantasy`
  с проверками ([index.md](index.md) §3, [../case-orcsday.md](../case-orcsday.md));
- проверка с кубиком (`2d6 + stat`) поддержана в MVP 0.65: `compare` хранит формулу,
  движок бросает кубик и вычисляет выражение; Fallout-проверки навыков дополнительно
  списывают мораль `(1d6 − навык) × 4`;
- сцена с проверкой не имеет `next`/`variants`: выход задают `success`/`failure`.

## 4. Бои

Боевой блок книги:

```text
Охранник, вооружение – боевой винчестер: очередь - 5d6
АТАКА 2
ЗАЩИТА 14
ЖИЗНИ 65
```

превращается в запись `mechanics.yaml`:

```yaml
combat:
  - scene: "4"
    enemy:
      name: Охранник
      attack: 2
      defense: 14
      health: 65
      weapon: "5d6"
    win: "320"
    lose: "—"
```

`АТАКА` → `attack`, `ЗАЩИТА` → `defense`, `ЖИЗНИ` → `health`, урон оружия → `weapon`.
Если книга не говорит, куда идти при поражении, `lose` не выдумывается: движок
MVP использует общий экран смерти; случай фиксируется в `review.md`.

## 5. Деньги, опыт, перки

- деньги — `stats.yaml`, диапазон `0…N`; цены в тексте остаются текстом, пока
  торговля не описана отдельно;
- опыт — `stats.yaml`; награда «плюс одно очко опыта» → эффект `stat: experience +1`;
- перк — флаг `perk_<латиницей>`; выдача перка → `set` на сцене;
- уровни, если книга их отрицает («уровней нет»), не вводятся.

## 6. Формат пакета

| Файл | Нужен |
|---|---|
| `story.md` | да |
| `game.yaml` | да, `type: rpg` |
| `stats.yaml` | да |
| `items.yaml` | да, если есть инвентарь и оружие |
| `flags.yaml` | да, если есть перки/события |
| `mechanics.yaml` | да: `checks` и `combat` |
| `illustrations.md`, `soundtrack.md` | по общим правилам |

## 7. Что расширим в движке

| Возможность | Статус |
|---|---|
| статы, предметы, флаги | есть |
| проверки по стату/навыку | расширение: `mechanics.yaml → checks` |
| бои Fighting Fantasy (`count`/`attack`/`health`) | есть в MVP: `combat` |
| RPG-бой с защитой/навыками | расширение |
| выбор оружия и лавка | есть для FF; RPG-торговля — позже |
| опыт и перки | частично (стат + флаг) |

## 8. Порядок разбора

0. проверить, не координатная ли книга: если достижимость прямыми рёбрами ниже
   половины, искать «параграф ± число» и заводить `codes.yaml` ([codes.md](../codes.md));
1. выписать характеристики, навыки, деньги, опыт из предисловия и листа персонажа;
2. найти проверки и записать в `checks`;
3. найти боевые блоки и записать в `combat`;
4. найти предметы, оружие, расходники — в `items.yaml`;
5. сцены с эффектами (потеря/награда/перк) — `stat`/`set`;
6. ссылки и выборы — по общим правилам;
7. проверки шага 10 и `review.md`.

## 9. Проверки

- `C_CHECK_INCOMPLETE` — у проверки нет исхода;
- `C_CHECK_UNSUPPORTED` — проверка не выражается текущим форматом (в MVP 0.65
  основные проверки поддержаны);
- `C_COMBAT_INCOMPLETE` — у боя нет `count`, `win` или особых полей;
- `C_COMBAT_UNSUPPORTED` — бой найден, но не описан; для Fallout MVP 0.65 есть
  отдельный слой `d20 + навык`, броня, несколько врагов;
- `C_STAT_AMBIGUOUS` — неясно, к какому стату относится изменение;
- `C_META_MISSING` — нет `title`, `language`, `status` или `type`.

## 10. Пример из набора

**Fallout II: По Ту Сторону Баррикад** (Денис Морозов, v1.04.5): 236 страниц,
~599 параграфов, характеристики (сила, ловкость, обаяние, интеллект, удача),
навыки с проверками, блоки `АТАКА/ЗАЩИТА/ЖИЗНИ`, деньги и опыт, инлайн-выборы вида
«– 95, – 118, – 366». Книга координатная: переходы задаются кодами «параграф ±
число» (§139), поэтому разбор использует [codes.md](../codes.md). Итог: 600 сцен,
953 прямых перехода, 44 кода, 599 сцен достижимо с кодами; 17 проверок и 39 записей
боёв в `mechanics.yaml`; 599/600 сцен совпали с книгой пословно.
