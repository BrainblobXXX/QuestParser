# Типы книг-игр и их определение

> Часть инструкции QuestRules. Точка входа — [AGENTS.md](../../AGENTS.md).
>
> Шаг 0.5 пайплайна: определить тип книги и подтвердить его у человека. От типа
> зависит, какие правила разбора и какие файлы пакета применяются.

## 1. Зачем тип

Книги-игры устроены по-разному: одна только ветвится, другая считает характеристики
и бросает кубики, третья ведёт полноценную ролевую систему с навыками и опытом.
Если применить правила одного типа к другому, получится пакет, который движок не
прочитает: например, бой пытаются выразить выбором, а проверку навыка — флагом.

Тип фиксируется в `game.yaml`:

```yaml
type: storybook   # storybook | fighting-fantasy | rpg | hybrid
```

## 2. Типы

| Тип | Что это | Пример из набора |
|---|---|---|
| `storybook` | ветвление и выборы, механик нет или почти нет | AnyCost, Quest, SteelRat |
| `fighting-fantasy` | характеристики, кубики, бои раундами, расходники | ZombieBlood |
| `rpg` | навыки, проверки, опыт, торговля, бои, инвентарь | Fallout II |
| `hybrid` | признаки двух типов, ни один не доминирует | — |

## 3. Сигналы

Признаки собираются по тексту до разметки сцен:

| Сигнал | Что искать | На что указывает |
|---|---|---|
| лист персонажа с характеристиками | «лист персонажа», «запишите значение», пустые графы | FF / RPG |
| характеристики | сила, ловкость, обаяние, интеллект, удача, выносливость | FF / RPG |
| кубики | «бросьте кубик», `2d6`, `1d6+5`, «кубик» рядом с числом | FF / RPG |
| бои | «АТАКА», «ЗАЩИТА», «ЖИЗНИ», «раунд», «урон» | FF / RPG |
| проверки | «проверка по навыку», «если ваша ловкость выше», «киньте проверку» | RPG — но проверка **способности** (`2d6 + Удача`) без навыков, опыта и торговли даёт FF, см. §5 |
| опыт и уровни | «опыт», «уровень», «перк» | RPG |
| деньги | «золотых», «долларов», «монет», «рублей» | FF / RPG — вместе с другими механиками (бои, характеристики, проверки); деньги без них дают `hybrid` (§5) |
| расходники | «аптечка», «еда», «патроны», «зелье» | FF / RPG |
| коды | «Запишите «10»!», «Если записано «2»» | storybook |
| достижения | «Если отмечено «…»», «получено достижение», лист персонажа из достижений | storybook (флаги) |
| главы | заголовки «Глава N» | storybook |
| дубли прозы | одинаковые абзацы с разными концами | storybook |
| инлайн-выборы | две и более ссылки внутри одного абзаца | любой |

Подсчёт простой: если есть бои и характеристики — `fighting-fantasy`; если к ним
добавлены проверки навыков, опыт и торговля — `rpg`; если механик нет — `storybook`;
если есть только деньги (без боёв, характеристик и проверок) — `hybrid`.

**Проверки способностей — не признак `rpg`.** Книга может просить «брось `2d6` и
прибавь Удачу, сравни с Оркишностью + 5» — это проверка характеристики, а не навыка.
Если при этом нет навыков, опыта и торговли, тип остаётся `fighting-fantasy`;
`rpg` начинается там, где есть навыки/опыт/торговля или проверка по навыку.
Обратный случай — книга с четырьмя способностями, кубиком и боями, но без
`stamina`/`skill`: её правила ближе к FF, и `rpg`-шаблон ей не подходит
([../case-orcsday.md](../case-orcsday.md)).

## 4. Порядок определения

1. собрать сигналы и посчитать их;
2. предложить тип с обоснованием: какие сигналы найдены, какие нет;
3. **спросить человека и получить подтверждение** — тип не ставится молча;
4. записать `type` в `game.yaml`;
5. если тип `hybrid` — общий вопрос о типе плюс запись `C_TYPE_HYBRID` по каждому
   моменту, где правила типов расходятся.

Пример вопроса:

```text
ТИП КНИГИ: fighting-fantasy?
признаки: лист персонажа — да, кубики — да (2d6+20),
бои раундами — да, проверки навыков — нет, опыт — нет.
подтвердить или указать другой тип?
```

## 5. Смешанные и неопределённые книги

- **`hybrid`** — признаки двух типов сопоставимы. В `game.yaml` ставится `hybrid`,
  а в `review.md` — `C_TYPE_HYBRID` по каждому спорному месту: «бой описан как
  выбор», «проверка замаскирована под выбор» и т.п.;
- **деньги как единственный сигнал** — суммы в каждой сцене без боёв, характеристик
  и проверок: это `hybrid`. Деньги моделируются статусом `money`, но условий на них в
  книге нет ([../stats.md](../stats.md) §8.1.1, [../case-2500.md](../case-2500.md));
- **тип не определён** — разбор не продолжается: сначала человек выбирает тип.
  Ставить `storybook` по умолчанию запрещено: это скрывает механики;
- **книга поменяла тип по ходу** (например, первая половина линейная, вторая с
  боями) — тип по большинству, спорные сцены в ревью.

## 6. Влияние типа на пайплайн

| Шаг | storybook | fighting-fantasy | rpg | hybrid |
|---|---|---|---|---|
| Выборы в прозе | да | да | да | да |
| Дубли прозы | да | редко | редко | по типу |
| `stats.yaml` | нет | да | да | да, если есть деньги или статусы |
| `mechanics.yaml` | нет | да (проверки способностей, бои, ставки) | да (проверки, бои) | по найденным механикам |
| `items.yaml` | редко | да | да | по найденным предметам |
| Деньги и опыт | нет | деньги | деньги + опыт | деньги; опыт — если есть |
| Коды «запишите» | да | нет | нет | если есть |

`hybrid` — объединение правил тех типов, признаки которых найдены: файлы заводятся по
фактическим механикам, а не «на всякий случай».

Правила каждого типа — в отдельных документах:

- [storybook.md](storybook.md);
- [fighting-fantasy.md](fighting-fantasy.md);
- [rpg.md](rpg.md).
